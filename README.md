# Ballistics

Ballance 地图的静态分析器。

输入一张地图的静态碰撞几何，输出值得尝试的球轨迹，每条轨迹附带一份证明：按已知的物理规则，它确实可行。

## 设计

- **手写的是物理，不是路线。** 球怎么受力、怎么滚、怎么碰，写成规则；路线由搜索在这套规则里找出来，不靠逐关补规则。
- **几何从粗到细。** 粗层只用来看全局结构和提候选；细层是引擎实际碰撞用的三角面本身。只有细层的计算能写进证明。
- **证明是一根管子。** 每一段给出进入时允许的位置和速度范围、保证的离开范围、用到的规则和余量；前一段的离开范围落在后一段的进入范围里。管子的宽度就是容错率。
- **引擎不参与搜索。** 确定性的无头引擎只做两件事：标定物理规则的误差界；事后当裁判，复核提出的轨迹。

第一个验收目标：第 1 关只靠球和静态网格，不依赖任何机关，从出生点到飞船。

### 几何核的验证

用一条完整的第 1 关引擎轨迹（20,483 帧）逐帧核对球心到三角面的距离：

- 球从不进入三角面，全程最小间隙 0.0099。
- 贴地滚动时间隙的中位数是 0.0141，这是引擎自己的接触余量。

## 数据和导出

分析器读的是每关两个文件：

- `L<nn>-mesh.npz`：引擎实际碰撞用的三角面（世界坐标）、每个三角面属于哪个实体、是不是钢轨，以及每个实体的摩擦和弹性系数。
- `L<nn>-map.json`：出生点、各盘点、飞船的位置，以及出生时的球种。

它们由导出器生成：让无头引擎把关卡加载一次，从关卡数据里读出来。球不会被驱动，除了关卡自己的启动过程之外不做任何物理推进。

```bash
python -m ballistics export --level 1 --out data --engine-root <游戏目录> --engine-build <无头引擎可执行文件> --instance <空闲的无头实例标签> --ballrain <Ballrain 检出目录>
```

提取什么、怎么存，由本项目的 `ballistics/export.py` 决定。和无头引擎通信借用的是 Ballrain 项目的客户端，所以导出时需要一份 Ballrain 的检出；分析器的其余部分不依赖它。

这些文件和引擎轨迹来自游戏本身，不放进仓库。本地放在 `data/` 下：

```
data/L01-mesh.npz
data/L01-map.json
data/traces/SR01_1_14_457_264.txt
```

也可以用环境变量 `BALLISTICS_DATA` 指到别的目录。没有这些文件时，依赖真实数据的测试会跳过。

## 运行测试

需要 Python 3.11 以上，以及 numpy、numba、pytest。

```bash
python -m pytest
```
