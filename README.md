# Ballistics

Ballance 地图的静态分析器。

输入一张地图的静态碰撞几何，输出值得尝试的球轨迹，每条轨迹附带一份证明：按已知的物理规则，它确实可行。

## 设计

- **手写的是物理，不是路线。** 球怎么受力、怎么滚、怎么碰，写成规则；路线由搜索在这套规则里找出来，不靠逐关补规则。
- **几何从粗到细。** 粗层只用来看全局结构和提候选；细层是引擎实际碰撞用的三角面本身。只有细层的计算能写进证明。
- **证明是一根管子。** 每一段给出进入时允许的位置和速度范围、保证的离开范围、用到的规则和余量；前一段的离开范围落在后一段的进入范围里。管子的宽度就是容错率。
- **引擎不参与搜索。** 确定性的无头引擎只做两件事：标定物理规则的误差界；事后当裁判，复核提出的轨迹。

## 路面和钢轨

球会碰到的只有两类东西：路面和钢轨。两者在碰撞上是一回事，都是三角面，物理核对它们用同一条接触规则。

钢轨另外还要知道“它是一根什么样的管子、往哪走”，这由钢轨提取给出：

- **截面**：钢轨的截面是正八边形，八个角都在同一个圆上。大约一半的截面缺最下面那个角（底部是开口的），接头和端头处角更少。
- **管子**：先找出哪些顶点属于同一圈，再过这一圈的角求圆，圆心就是轴线上的点，圆的半径就是管子的半径。角都在圆上，所以这一圈完整不完整都能求准；用一圈角的平均位置当圆心则不行，缺角时会偏。
- **走线**：两根平行、间距够球架在中间的管子是双轨，球心走在两根中间偏上；其余的是单轨，球心在管子正上方。粗管是关卡设计用来走的钢轨，细管是护栏、立柱和饰边，接近竖直的是立柱。

第 1 关的结果：

- 14,358 个钢轨三角面，1,110 圈截面（567 圈八个角，506 圈七个角，其余是接头和端头），拟合出 1,051 段管子。
- 半径两档：细的 0.247，粗的 0.351（少数 0.36）。
- 所有钢轨顶点都落在拟合出的管子表面上：距离中位数 0.0010，最大 0.033。
- 和另一个项目对同一批钢轨的拟合结果比：轴线总长相同（2,417），双方的每一段都在对方的轴线上，最大偏差 0.011。
- 识别出 12 条双轨（总长 711）、8 条粗的单轨（其中一条长 84，沿着螺旋外侧，比双轨高，就是高手当单轨骑的那根护栏）、33 条细的护栏。

## 物理核和引擎差多少

物理核把球当成一个刚性球：每个物理步先按当前速度移动，再加阻尼、按键推力和重力，然后在接触点上加法向冲量和摩擦冲量。滚动不是单独的规则，是摩擦冲量的结果。球的参数用游戏自己的表，没有调过任何系数。

它能从这几条规则直接得出游戏里量到的数：木球平地单键的速度上限 15.9、双键 22.5，石球从静止能守住的坡度上限是推力比重力（约 16.9°）。

和一条完整的第 1 关引擎轨迹对比（`python -m ballistics calibrate`）：

**往前算一步**（速度误差，单位每物理秒；球速约 12，一个键每步加约 0.2）：

| 球在什么上 | 步数占比 | 中位数 | 90% | 99% |
|---|---:|---:|---:|---:|
| 空中 | 38% | 0.0000 | 0.31 | 0.43 |
| 路面 | 40% | 0.0084 | 0.20 | 1.1 |
| 钢轨 | 10% | 0.012 | 0.16 | 0.64 |
| 落地那一步 | 3.5% | 0.24 到 0.41 | 1.8 到 2.7 | 8 |

**不做任何修正连续往前算**（位置误差，单位；从引擎的状态出发，用同样的按键）：

| 时长（游戏秒） | 途中只在路面上滚 | 途中有腾空 | 全部 | 这段时间球走了多远 |
|---|---|---|---|---:|
| 0.25 | 中位 0.15，98% 在 1 以内 | 中位 0.19，96% 在 1 以内 | 中位 0.17 | 约 7 |
| 0.5 | 中位 0.14，95% 在 1 以内 | 中位 0.47，80% 在 1 以内 | 中位 0.37 | 约 13 |
| 1.0 | 中位 0.23，86% 在 1 以内 | 中位 1.2，45% 在 1 以内 | 中位 1.1 | 约 27 |
| 2.0 | 样本太少 | 中位 8.1 | 中位 8.1 | 约 50 |

怎么读这些数：

- 在路面上滚动，一秒之内的预测误差是路宽（5）的一小部分。
- 带腾空的轨迹，半秒内中位误差不到半个单位，一秒后约 1.2；两秒以上的开环预测不能当证明用，管子要分段。
- 这条轨迹是 TAS 走的高手路线，腾空多，是最难的对比对象。
- 目前只和这一条轨迹对比过，只有木球。

### 落地和碰撞的规律

从这条轨迹里取出 65 次落地，逐次量出来的：

- **反弹**：离开时沿法线的速度是撞上去时的 0.245 倍，和撞击速度无关（从 2 到 21 都一样），路面和钢轨一样。0.245 正是球和路面两个弹性系数的几何平均（木球 0.2，路面和钢轨 0.3）。
- **撞击那一步**：球停在离表面 0.010 的位置；这一步的阻尼、推力和重力先作用，再反弹。
- **摩擦**：两个摩擦系数相乘（0.8 × 0.7 = 0.56），和引擎自己的接触记录一致。
- **自转很重要**：落地时摩擦改变多少水平速度，取决于球带着多少自转。数据里没有直接记录自转，是从逐帧的朝向反推的：大小对得上（和纯滚动只差 4%），方向和纯滚动的中位偏差约 17°，原因还没查清。用上它之后，落地一步的误差中位数从 1.8 降到 0.24。

## 第 1 关目前解到哪一步

**粗层**（`coarse.py`）在精确几何上每隔 1 个单位取一个“球能被托住的位置”，加上钢轨走线，连成图。它在第 1 关一个小节也接不通（箱子、石块、成排的道具球挡着，过去要靠带速度的腾空）。现在它只给细层指方向。

**细层**（`fine.py`）直接在物理核里搜索按键：从盘点的重生位置静止出发，每次选一个已到过的状态，按住九种推力之一若干步，新的或更快到达的状态留下；一半的选择偏向离目标近的状态。物理核的一步编译后约 8 微秒，一个小节搜几十秒到几分钟。

两种模式：

* **严格**：摆放的东西（机关、箱子、道具球）一碰就算失败；球连续 10 步以上只挂在路面侧棱上也算失败。
* **宽松**：道具球当作不存在（假定会被撞开），允许挂在侧棱上。

第 1 关的结果（木球，按键只有方向键，时间是轨迹本身的游戏秒，不是最优）：

| 小节 | 严格 | 宽松 | 断点是怎么过的 |
|---|---|---|---|
| 1 出生点 → 盘点 1 | 找到，61.2 秒，搜索 136 秒 | 找到，53.6 秒 | 箱子区：从高处钢轨尽头以 15.7 的速度飞出，横过 18、下落 9.5，落在墙顶上，再落进箱子后面的通道 |
| 2 盘点 1 → 盘点 2 | 找到，28.7 秒，搜索 18 秒 | 找到，29.7 秒 | 石块：提前离开钢轨落到平台边沿，沿北侧边沿助跑 16 个单位到 13.1 的速度，在拐角处跳上坡道最低的一端（比边沿高约 1） |
| 3 盘点 2 → 盘点 3 | **没找到**（221 万次展开，560 秒） | 找到，18.0 秒 | 平台上横着一排 6 个道具球（5 个石球、1 个纸球，间距约 4.5），把路占满。严格模式停在它们前面；宽松模式是从纸球的位置穿过去的，等于假定纸球被撞开 |
| 4 盘点 3 → 飞船前 | 找到，39.1 秒，搜索 48 秒 | 找到，45.6 秒 | 路面上没有挡路的东西；目标是飞船前最后一段路面，飞船本身的形状不在网格里 |

对照：录像（SR 1:14.457）全关 74.5 秒。

**这些结果值多少**：它们是手写物理核的轨迹，不是游戏的。搜索会找到物理核允许的任何走法，包括物理核不准的地方。每条轨迹都附带它依赖什么：

* 腾空段的起落点、距离、起飞速度；
* 挂在侧棱上的段落（这种接触没有标定过）；
* 每一游戏秒的敏感度：把状态扰动一点（位置 0.03、速度 0.3），按键不变，一游戏秒后还有多少留在轨迹 1.5 以内。严格模式下，第 1 小节 121 个窗口里 85 个全部留住、14 个不到一半留住；第 2 小节 56 个里 40 个和 5 个；第 4 小节 77 个里 56 个和 5 个。不到一半留住的地方就是这条轨迹最靠不住的地方（多是落地和撞棱）。

所以它们是**候选**，要等引擎跑过才算数。“没找到”只说明在给定的预算里没找到，不是“不可能”。

已知的不足：

* 推箱子、推道具球、滑动的石块都没有建模。第 3 小节按正常玩法是把纸球推开，这个分析器现在算不了；
* 轨迹是搜索碰到的第一条，没有优化，也没有分段做成证明；
* 飞船的形状不在网格里（路面在飞船前 21.9 处结束）；
* 只有木球；只做了第 1 关。

## 每条规则的依据

每条规则和常数都要说明来源，分三种：**实测**（在引擎数据上量的，写明数据量）、**读取**（从游戏自己的表或记录里读的）、**假定**（没有核对过）。只靠“假定”的东西不能进证明。代码里常数旁边写着同样的标注。

| 规则 | 依据 |
|---|---|
| 碰撞体是 `Phys_Floors` 和 `Phys_FloorRails` 的网格 | 实测：第 1 关 21,763 个三角面和运行中的游戏逐个相同 |
| 球半径 2，贴地时离表面 0.010 到 0.020 | 实测：20,483 帧，球从不进入三角面 |
| 先按旧速度移动，再更新速度；阻尼、重力、推力的数值 | 读取游戏的表；实测：空中 3,824 步，误差中位数为 0 |
| 按键方向随视角的换算 | 实测：视角 1、2，五种按键组合，共 1,609 步，完全吻合。视角 0、3 和其余按键组合数据里没有，未核对 |
| 滚动是接触点摩擦的结果 | 推导；它的预测与实测相符（速度上限 15.9、22.5；路面上一步误差 0.008） |
| 摩擦系数是两个系数相乘 | 读取：引擎自己的接触记录（0.8 × 0.7 = 0.56） |
| 反弹系数是两个弹性系数的几何平均 | 实测：65 次落地，撞击速度 2 到 21，木球对路面和钢轨 |
| 撞击那一步先更新速度再反弹；球停在离表面 0.010 处 | 实测：21 次单点落地和全部 65 次落地 |
| 能翻上的台阶不高于 1.5（粗层） | 实测一例：录像在第 2 小节翻上 1.45 高的台阶（到达时横向速度约 15，按着键）。更高的没有依据，不提出 |
| 编译版的一步和文字版的一步是同一个物理核 | 实测：6,800 多个录像状态上逐步对比，位置、速度、自转相差小于 1e-9；120 步连续运行相差小于 1e-7 |
| 球掉到周围 32 到 40 个单位内所有表面以下就放弃 | 搜索的界限，不是物理规则 |
| 道具球会被撞开（宽松模式） | **假定**，没有建模；石球比木球重 5 倍，多半撞不开 |
| 球挂在侧棱上（球心在棱的外侧） | 物理核按接触冲量算，**没有标定过**；严格模式不许连续超过 10 步 |
| 撞击速度低于 1 时不反弹 | **假定**：数据里没有慢于 2 的落地，真实门槛不知道 |
| 多个接触点时逐点求冲量 | **假定**的解法；引擎自己的解法不知道，吻合程度以标定表为准 |
| 石球、纸球 | 参数是读取的，但没有和引擎对比过；纸球在游戏里不是球形 |
| 钢轨截面是正八边形，半径 0.247 和 0.351 | 实测：第 1 关 1,110 圈截面 |
| 双轨的两根轴线相距 3.80 | 实测：第 1 关全部 12 条双轨 |
| 粗管是用来走的钢轨，细管是护栏 | 对第 1 关布局的解读，不是游戏给出的事实；球在物理上两种都能骑 |
| 立柱和双轨配对的判别门槛 | **假定**的工作门槛 |
| 球的自转（标定时用） | 从逐帧朝向反推：大小与纯滚动差 4%，方向中位偏差 17°，原因未查清，**不可靠** |

## 输入：地图文件

输入是一张 Ballance 地图的 `.nmo` 文件，原版关卡和自制图都一样。直接读文件，不启动游戏。

```bash
python -m ballistics export <地图.nmo> --out data
```

它写出两个文件：

- `<名字>-mesh.npz`：玩家球会碰到的固定物体的三角面（世界坐标）、每个三角面属于哪个物体、是不是钢轨，以及摩擦和弹性系数。
- `<名字>-map.json`：出生点、重生点、各盘点、飞船、小节数、每个小节里放了什么（机关、道具球、分数球等占位物体的类型和位置）、死亡区。

哪些东西会碰到球，按游戏自己的规则来：`Phys_Floors` 和 `Phys_FloorRails` 两个组里的物体，以各自的网格作为碰撞形状；`Phys_FloorStopper` 只挡机关和道具球，不挡玩家球，所以不算。游戏在每一关还自带一个固定在原点的边长 4 的方块，也一并加上。

地图文件里没有出生时的球种（游戏按关卡槽位决定），也没有机关的部件（它们来自游戏自带的模板）。

### 读 nmo 需要的库

`.nmo` 的格式由 libcmo21 项目的 BMap 库解析，通过它的 Python 绑定 `pybmap` 调用。这两样不在本仓库里。查找顺序：`--bmap` 给的目录、环境变量 `BALLISTICS_BMAP`、作为 Blender 扩展安装的 Ballance Blender Plugin（bbp_ng，它自带这个库）。

### 验证

- **和游戏里的碰撞体一致**：第 1 关从 `Level_01.NMO` 读出的 21,763 个地图三角面，和运行中的游戏为固定物体持有的三角面逐个相同，坐标差为 0。出生点和三个盘点的位置也相同。
- **和游戏里球的运动一致**：用一条完整的第 1 关引擎轨迹（20,483 帧）逐帧核对球心到三角面的距离，球从不进入三角面，全程最小间隙 0.0099；贴地滚动时间隙的中位数是 0.0141，这是引擎自己的接触余量。

## 本地数据

地图文件、导出的网格和引擎轨迹都来自游戏本身，不放进仓库。本地放在 `data/` 下：

```
data/maps/Level_01.NMO
data/Level_01-mesh.npz
data/Level_01-map.json
data/traces/SR01_1_14_457_264.txt     引擎逐帧轨迹，用来核对几何和标定物理
data/engine/L01-mesh.npz              从运行中的游戏读出的三角面，只用来和上面的导出结果比对
```

也可以用环境变量 `BALLISTICS_DATA` 指到别的目录。没有这些文件时，依赖真实数据的测试会跳过。
