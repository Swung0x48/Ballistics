# 已经接进求解的机关和物体

目录（[things.md](things.md)）里的东西一种一种接进求解。这一页每种一节，写明：模拟了什么，规则和依据，拿什么对照过，在规划里怎样用，还没做的是什么。
一种机关算接完，要粗层规划、跟随器、细搜三层都用得上它。
规则用到的数都从目录里读，代码里不另写一份；目录里哪个数错了，改目录。只供粗层用的几何容差不是游戏的数，另标【假】。

| 条目 | 状态 |
|---|---|
| 分数球和生命球（P_Extra） | 已接：路线吃到什么、得多少分和几条生命 |
| 风扇（P_Modul_18） | 已接：不再是障碍；物理核里有它的竖直推力。只算木球，纸球靠它上升的路还用不上 |
| 变球器（P_Trafo），连带石球 | 已接：按游戏的规则触发；粗层规划、跟随器、细搜都能穿过木变和石变，球种跟着路线走。纸变仍然不进 |
| Dome（P_Dome） | 已接：它所在小节的固定几何，带自己的摩擦和弹性；粗层可以规划从它上面走 |
| 道具球（P_Ball） | 已接：会动的球体刚体，物理核里和玩家球一起解；粗层、跟随器、细搜都能撞开它们走 |
| 箱子（P_Box） | 已接：只滑不翻的方块，和道具球一样是会动的刚体；三层规划都能推着它走。粗层还不会规划“踩着箱子走” |
| 落石（P_Modul_34） | 已接：箱子和挂在竖直滑轨上的路块，两个会动的方块；粗层、跟随器、细搜都认它们。默认区域分析另有“下层推开、绕回上层通过”的状态机，不用于 `--roll` |
| 活式木栅栏（P_Modul_01） | 已接：滑块是三块形状合成的刚体，只碰自己的凹槽；粗层记得它开没开，关着挡路，石球推开以后才过得去 |
| 推板（P_Modul_25） | 已接：物理核里第一个绕铰链转的刚体；托座（Phys_FloorStopper）也接了。粗层记得推没推倒：木球、石球从前方路面推倒它过去，倒下以后两个方向都能过 |
| 纸球 | 已接：求解器会算的球种；球种是粗层状态的一部分，纸球有风扇的上升边，也有连乘两个风扇的；物理核里仍是球体替身，贴地偏快 |
| 跷跷板（P_Modul_30） | 已接：推板那种铰链体，Floor 组；粗层记得哪头低，从低端过板，石球过板就把它翻过来。石球在坡上偏弱 |
| 软木桥（P_Modul_29） | 只接进了粗层的区域分析：木球、纸球两个方向都能过，石球不能；物理核里还没有它，`solve --roll` 不用它 |
| T 型板（P_Modul_37） | 只接进默认区域分析：木球或石球推倒，绕到另一条路从横头过；`--roll` 仍不模拟它 |
| 箱式浮板（P_Modul_41） | 只接进默认区域分析：每列按球种放行过列、侧面及末端离开的连接，不设状态位；`--roll` 不用它 |
| 双向挡板（P_Modul_19） | 只接进默认区域分析：A / B 姿态各填一段缺口，木球或石球在指定侧拨动并过另一条路；`--roll` 不用它 |
| 其余机关 | 没接：机关仍然是“推演中不许碰” |

## 分数球和生命球

代码在 `ballistics/extras.py`。

**它不改变球的运动。** 分数球和生命球没有刚体，球直接穿过；导出网格时本来就没有放它们。接进来的是“一条路线吃到了什么”：沿着路线已有的每一步的球心位置，一帧一帧判定。评估按 132 fps，一帧就是一个物理步。

### 规则和依据

| 规则 | 数 | 依据 |
|---|---|---|
| 吃分数球：球心到它的摆放点三维距离小于 3，当帧 +100 | 3 | 测（原版记录） |
| 吃生命球：球心到它的摆放点三维距离小于 4.5，生命 +1 | 4.5 | 测（原版记录） |
| 只有当前小节的道具在场，别的小节的吃不到 | | 读（脚本）；原版记录没有检验到（见下） |
| 当前小节在过盘点时换：球心到盘点的大火焰三维距离小于 6.5；大火焰在盘点原点正上方 1.4948 | 6.5、1.4948 | 读（脚本）；高度是测（重建引擎） |
| 过盘点那一帧之后第 2 帧旧小节的道具撤掉，第 6 帧新小节的道具放好，检测再晚 1 到 2 帧打开：这里按第 8 帧起算 | 2、6、1–2 | 死亡拆建时测（重建引擎），过盘点时是推出来的 |
| 下一个盘点从过盘点那一帧之后第 12 帧起才算 | 12 | 推 |
| 吃分数球后 6 个分数小球追球，每追上一个 +20，连内核一共 220 | 100 + 20 × 6 | 测（原版记录、零售版） |
| 分数小球按“过盘点前按 Esc 收齐”算：每个吃到的分数球记 220 | 220 | 项目主人定的；暂停能收齐是测（原版记录） |

“当前小节”是按上面的规则沿路线自己算的，不用求解器分小节的界线：求解器一个小节的轨迹可以在离大火焰还有一段的地方就交给下一小节。

分数小球不影响路线。球在动时它们到齐要 1.97 到 13.80 游戏秒（原版记录里没被打断的 28 次，中位 4.48），小节被撤掉时没到的作废；但过盘点前按 Esc 暂停，它们照飞、照加分，游戏的钟是停的。原版记录里带着分数小球暂停的 39 次，31 次全部收完，7 次收了一部分，1 次（只停了 19 帧）没收到，暂停要停够（实际时间约 0.2 到 0.8 秒）。所以这里不算它们的飞行，每个吃到的分数球直接记 220；什么时候按 Esc 是跑这条路线的一方的事。

`marginal`（贴边）：球心离道具最近时，到判定距离的差小于球那一步走的路程。吃到的贴边，说明路线稍偏一点就吃不到；没吃到的贴边，说明稍偏一点就吃到了。

### 对照

把 24 条原版记录（2002 年原版物理库回放录像的逐帧记录，132、240、264 fps 三种）里每一帧的球心位置喂给这段代码，和记录里实际发生的比。每条记录比到第一次死亡或通关为止（这里不模拟死亡）。

| | 记录里 | 判定对上的 | 差几帧 |
|---|---|---|---|
| 吃分数球 | 196 次 | 195 次 | −1 到 +1；132 fps 的 4 次是 0、0、0、+1 |
| 吃生命球 | 43 次 | 43 次 | 0 到 +2（生命 +1 的那一帧相对判定的那一帧） |
| 过盘点 | 100 次 | 100 次 | 0 到 +2（盘点事件相对判定的那一帧） |

- 没有多判：判定吃到而记录里没吃的是 0 次，盘点也是 100 对 100。
- **记录没有检验到的规则**：24 条记录里球一次也没有进过“不是当前小节的道具”的判定距离，所以“别的小节的吃不到”只有脚本作依据。吃道具离上一次过盘点最近也隔了 446 帧，两次过盘点最近隔 851 帧，所以第 2、8、12 帧这几个延迟也没有被检验到，依据只有脚本和重建引擎。
- 这几个延迟在原版关卡里不起作用：13 关的 247 个分数球和生命球（都在某个小节里）离自己小节开始的地方（出生点、重生点、上一个盘点的大火焰 6.5 以内）最近的也比判定距离远 27。
- 没对上的 1 次：记录里吃到了，但记录的球心离它最近是 3.0003，判定没吃，标成了贴边。
- −1 只出现在 240、264 fps：这些记录里球的位置每个物理步才更新一次，一帧里脚本看到的球比记录的靠前。
- 所以判定的那一步准到 ±1 帧；贴着判定距离擦过去的路线，吃不吃得到是不确定的，用 `marginal` 标出来。

这次对照改了目录里的两处：原来写的“按上一帧末的位置判、193 次吃到时距离 2.416–3.006”换成了上面的说法；分数小球到齐的时间原来只有 3 次样本（3.96–7.92 游戏秒），换成了 28 次（1.97–13.80）；这个数现在只是记在目录里，判定不用它。

仓库里的测试（`tests/test_extras.py`）只用假想的路径检查规则；和原版记录的对照要用游戏数据，脚本和结果在本机，不在仓库里。

### 在输出里

- `solve --roll` 打印每个小节时，多几行：路上吃到的每个分数球、生命球（第几游戏秒、吃到时和最近时的球距、分数），以及这个小节里没吃到的各自最近到多远。
- 路线清单 `<名字>-routes.json` 的每条路线多一项 `extras`，路线文件的 `meta` 多一项 `collected`，见 [files.md](files.md)。
- 留下断点的小节：断点之后的轨迹是把球摆到对面接着算的，那一段吃到的会列出来但标明不算。

第 1 关现有的标准路线（见 [level-1.md](level-1.md)）：第 1 小节吃到 1 个生命球和 2 个分数球，其中一个贴边（最近 2.95），另有一个分数球以 3.07 擦过没吃到，也是贴边；第 2 小节吃到 1 个分数球；第 4 小节一个都不经过。

### 没做的

- **搜索不会为了吃道具去绕路。** 求解器不以它们为目标，只报告路线顺路经过了什么。要专门去吃（HS 路线）是以后的事。
- **死亡**：吃过的生命球死亡后回来、分数球不回来，生命数决定还能死几次。这里都没有，因为求解器还不模拟死亡。
- **整关的分数**（Points 随时间减、每条生命 200 分）属于关卡流程，等接关卡流程时再算。这里只给道具本身的分。
- **生命球的显示**：生命球要球先进它 60 以内才显示、才能吃，每 5 到 20 帧查一次。没有建模：球不可能在 20 帧里从 60 外走到 4.5 内；小节刚建好时球离最近的道具也有 27 以上（13 关的地图都查过），显示来得及打开。
- **按 Esc 收分**是默认做了的（每个分数球记 220），但暂停本身不在路线里：路线不标在哪一步暂停、停多久。
- 变球期间球不在场、道具球吃不吃得到，都等接变球器和道具球时再说。

## 风扇

代码：`ballistics/fans.py`（从目录读数、从地图取当前小节的风扇），物理核的一步里多一项（`kernel._fans_pushing` 和 `_step` 里的一行，文字版 `physics.step_reference` 里是同一行）。

**这是第一个改物理核的。** 改了两件事：风扇不再是障碍；球在风扇的作用区里时，每个物理步多一个向上的冲量。

### 规则和依据

| 规则 | 数 | 依据 |
|---|---|---|
| 风扇没有刚体，转子和作用方块都不挡球 | | 读（脚本）；测（原版记录）：球心在方块里面的有 2 万多行，木球球心离转子的面最近 0.23（球半径 2） |
| 推力开着时，每个物理步在球心加一次世界 +Y 的冲量，速度增加 0.1 / 质量 | 0.1；木 0.0526、纸 0.5、石 0.01 | 读（脚本）；木、纸是测（原版记录），石是测（重建引擎） |
| 一步里的次序：阻尼、这个冲量、重力 | | 测（原版记录） |
| 几个方块同时作用时相加 | | 读（脚本）；原版记录里有 20 步是两个方块的量（都是纸球），判定对上 18 步 |
| 作用方块：风扇自己的坐标里 x、z 在 ±1 以内，y 在原点上方 1.14 到 17.14 | | 读（模板） |
| 推不推：游戏每帧拿球的网格盒（随球转动）和方块做一次盒测试，用的是上一步走完后的位姿，结果从下一步起生效 | | 读（脚本）；“看哪一步的位置”是测（132 fps 的原版记录） |
| 物理核不记球的朝向，改用距离：这一步开始时球心到方块盒的三维距离小于按球种的距离就推 | 木 2.75、纸 3.05 | 测（原版记录）：和记录最合的距离 |
| 只有当前小节的风扇推球 | | 读（脚本）；原版记录没有检验到（见下） |

### 对照

把 24 条原版记录里风扇附近（球心离某个方块盒 6 以内）每个不接触的物理步的起始位置和速度交给物理核走一步，比走完后的竖直速度。不接触的步里物理核只做移动、阻尼、风扇、重力，所以对不对只取决于风扇推没推、推了几个、次序对不对。

| | 步数 | 对上 | |
|---|---|---|---|
| 木球 | 795 | 776 | 97.6% |
| 纸球 | 19,303 | 18,642 | 96.6% |

- 对上的步，竖直速度和记录相差不超过 0.000002（记录是单精度的）。冲量的大小、相加和次序都对。
- **这两个百分比是在配距离的同一批步上算的。** 换样本检验：把记录分成两半，在一半上配距离、到另一半上看，木球对 352 / 359 和 417 / 434，纸球对 9,325 / 9,678 和 9,282 / 9,610，和上表差不多。132 fps 的木球只有 50 步，2.75 对 48 步，2.35 到 2.5 能全对：样本太少，没有据此改数。
- 没对上的步大多在方块盒的边上（木球没对上的步，球心到盒的距离中位是 2.92，判定距离 2.75）：那里推不推由球的朝向决定，物理核不知道朝向。另有十几步的速度变化根本不是风扇的整数倍，是没被标成接触的落地一类。
- “看哪一步的位置”：132 fps 的两条记录里，纸球按这一步开始时的位置判对 1,490 / 1,568 步，按上一步开始时 1,482，按这一步末 1,488。差别很小，取了最合的、也是脚本读出来的那一种。
- **记录没有检验到的**：记录里球从没进过别的小节的风扇的方块盒，“只有当前小节的风扇推”只有脚本作依据。
- 第 3 关的地图把一个风扇的占位物体（P_Modul_18_04）也列在了路面组里，导出的网格里它是一根实心柱子。三条经过它的原版记录里，球心在它的盒里各有 104 到 214 行：它不是刚体。13 关里这样的物体只有这一个。

### 纸球在风扇里

纸球才是风扇的正主，所以单独验证了一遍。物理核本来就能按纸球的质量和阻尼走（接触时把它当球体，那是粗略的；下面比的都是不接触的飞行，不涉及这一点）。

**盒边上推不推，物理核定不了。** 推不推随球心到方块盒的距离这样过渡（原版记录，只有一个方块在近处的不接触的物理步）：

| | 必推 | 各一半 | 必不推 |
|---|---|---|---|
| 纸球 | 2.0 以内（11,003 步全推了） | 3.05 | 3.6 以外（3,564 步全没推） |
| 木球 | 2.5 以内（236 步全推了） | 2.8 | 3.2 以外（454 步全没推） |

中间这一段由球的朝向决定。记录里没有球的朝向，只有角速度；我试过把角速度积分成朝向再做游戏的盒测试（8 种假定：世界坐标或球自己的坐标、每次出现从正的朝向起或接着上次、两种符号），没有一种比按距离判定更准（95% 对 96.6%）。所以朝向重建不出来，而且物理核把纸球当球体滚，也算不出它滚到风扇时的朝向。

因此物理核给三档判定距离：最合记录的一档（纸 3.05、木 2.75），以及下档（必推的距离：纸 1.96、木 2.0）和上档（可能推的最远距离：纸 3.6、木 3.47）。`World.of(..., fan_edge="least" 或 "most")` 用下档或上档。

**连续推演对整段飞行。** 从记录里一段不接触的飞行的第一步起，让物理核自己连续走完整段（水平推力取记录里的，竖直方向全由物理核算），比每一步的高度。纸球 253 段、25,167 步，其中 201 段被风扇推过：

| | 结果 |
|---|---|
| 最合的一档：段中最大高度差 | 中位 0.21；小于 0.25 的 134 段，小于 1.0 的 214 段，39 段超过 1.0 |
| 最差的一段 | 差 36.9：记录里球擦着盒边（水平 3.35）被推进了风扇柱升上去，物理核判成没推，球掉下去了 |
| 记录的高度落在下档和上档两条轨迹之间 | 24,530 / 25,154 步；整段都在之间的 228 / 253 段；最高点在之间的 249 / 253 段 |
| 出界的 | 最多低 1.9、高 2.6：到顶之后来回摆的相位不同，以及个别段两档都推了而记录没推 |

木球 25 段：24 段的最大高度差小于 0.25。

**从底座升起和悬停**（第 2 关一个带底座的风扇，纸球静止在底座上，不按键）：

| | 物理核 | 目录里的数 |
|---|---|---|
| 升到原点上方 19.14 | 172 步（三档都是） | 172 步（重建引擎上量的） |
| 悬停的高度（原点上方） | 最合的一档 19.85–20.41；下档 18.73–19.34；上档 20.37–20.98 | 几乎不转的 19.1–19.9（推出来的），翻滚着进来的 19.14–20.6（重建引擎上量的） |

结论：

- 推力本身（大小、次序、相加）和升起的时间是对的。
- 球在盒边上进不进风扇柱、悬停在多高，取决于朝向，物理核只能给范围：悬停高度的范围是 18.7 到 21.0，目录里量到的都在里面。擦着盒边进风扇的走法，两档的结果可以是“升上去”和“掉下去”之分。
- 所以以后规划纸球乘风扇的路线时，一条路线要在下档和上档下都成立才算稳；只在一档下成立的要标成“看朝向”。这一步还没做，因为求解器还不算纸球。
- 原版记录里没有悬停的段（球心在方块正上方或正下方、盒的高度范围以外的步只有 7 步），悬停高度没有原版的对照，只有重建引擎的。

仓库里的测试（`tests/test_fans.py`）用假想的风扇检查规则，并检查编译版和文字版的一步在有风扇时仍然是同一步；和原版记录的对照在本机。

### 在求解里

- 求解一个小节时，物理核里只有这个小节的风扇在推；跟随器、细搜、备选路线用的都是同一个物理核，不需要另外的规则。
- 导出网格时不再放风扇的部件，也不再把占位物体当路面。以前导出的网格文件不用重做：`coarse` 和 `solve` 读进来时会把这些去掉；按旧网格缓存的粗层图会被认出来、自动重建。
- 粗层的起飞边是不带风扇造的（它们只是提议）。

效果：

- 第 1 关没有风扇，结果不变。
- 木球吹不起来（一个风扇每步 +0.0526，重力每步 −0.303）。在风扇柱里木球下落的终速从 22.2 降到 18.4（每物理秒），飞过风扇上方会稍远一点。
- 第 2 到 13 关共 132 个风扇，原来每个都是一根 2 × 16 × 2 的实心柱子加一个转子，挡在路上；现在不挡了。
- 实际跑过的：重新导出第 1 关，网格和原来逐个三角面相同（27,665 个）；重新导出第 3 关，等于旧网格去掉 256 个假障碍的三角面。第 3 关第 5 小节的一个风扇里让木球从方块顶部落 30 步：竖直速度 −6.20，不算这个小节的风扇时是 −7.50，用旧网格则第 0 步就因为碰到“摆放物”而中止。第 1 关已存的四个小节的路线用新物理核重放，终点状态完全相同。
- **没有在有风扇的关卡上跑过 `solve`。**
- 第 3 关的粗层规划（不推演，只看地图）去掉这些假障碍前后几乎一样：第 5 小节仍然要 5 处链接，其中 3 处是 11 到 15 的上升，正是纸球乘风扇上去的地方，木球上不去。别的关没有重跑。

### 没做的

- 求解器现在会算纸球，风扇的上升边也有了（见“纸球”一节）；纸球滚动时仍是球体的粗略替身。
- **球的朝向。** 定不了（上一小节），用下档和上档两档距离把它框住；“两档都成立才算稳”的检查现在接进了求解器（见“纸球”一节）。
- **两层邻近检测**（先查水平 80，再查水平 7 并锁定那个球，之后才逐帧做盒测试）没有建模，也不需要。从地图算：51 个纸变变出的新球离同小节风扇轴最近 7.1，没有一个在 7 以内；72 个小节起点（重生点、上一个盘点）最近 15.7。推力在方块里才开，方块离轴约 4，新球和起点离方块都还有好几帧的路，两层检测来得及先查到；从 80 以外进来要赶在检查间隔里钻进方块，速度得过每物理秒 140，游戏里到不了。
- **当前小节**用的是求解器正在解的那个小节，不是按“球进盘点大火焰 6.5”算的那一刻。离盘点很近的风扇会有出入。
- 石球的判定距离没有样本，用了木球的。
- 风扇的朝向按摆放的轴算。132 个风扇的轴都是单位长度，只有第 13 关的一个倾斜了 1°，其余都是正的；倾斜的风扇没有单独对照过。

## 变球器

代码：`ballistics/trafo.py`（从目录读数、规则），物理核里触发的判定（`kernel._rollout`），求解器里球种跟着路线走（`staged.py`）。

变球器没有刚体，只按距离起作用。它对路线是一次状态的跳转：球种、位置、速度都换掉，时间过去 2.52 游戏秒。

### 规则和依据

| 规则 | 数 | 依据 |
|---|---|---|
| 每帧取离球心最近的一个变球器（三维，到变球器的原点）；它比 4.3 近而且和球不同种，就变球 | 4.3 | 读（脚本）；测（重建引擎）；测（原版记录，见下） |
| 最近的那个和球同种时什么都不发生，而且它挡住更远的异种 | | 读（脚本）；原版记录没有检验到 |
| 进 4.3 之后旧球再当 2 步刚体就消失 | 2 | 测（零售版 132 fps；原版记录） |
| 新球出现在变球器原点沿它自己的 y 轴 3 处，静止，从那一步起受重力；再下一步起按键起作用 | 3；332、333 | 测（零售版、原版记录），倾斜的变球器也是（原版记录两次） |
| 进来时的速度不保留 | | 测（原版记录：新球出现的那一行竖直速度正好是一步重力；水平速度在 132 fps 的 5 次里是 0，其余帧率下那一行可能已经带上一步按键的量，最大 0.325） |
| 在场的变球器：当前小节的 | | 读（脚本）。别的小节的也可能在场（见“没做的”） |

和以前的不同：以前把石变、纸变当成“以原点上方 2 处为心、半径 4.6 的禁区”，那个中心的高度是假定的；现在是游戏的规则本身，以原点为心、4.3，只对异种的球起作用。

### 对照

把 24 条原版记录里每一帧的球心和球种交给 `trafo.triggered` 判，和记录里实际的变球比：

| | |
|---|---|
| 记录里的变球 | 75 次，对上 74 次 |
| 没对上的 1 次 | 判定说变而记录没变：球心只有一行到了 4.299，是擦边 |
| 球心第一次进 4.3 的那一行到变球器原点的距离 | 3.998–4.300；前一行都在 4.302 以外 |
| 新球出现时相对变球器原点的位置（变球器自己的轴） | x、z 在 ±0.004 以内，y 2.9989–3.0008；其中两次是倾斜 13.5° 和 40.0° 的变球器 |
| 132 fps 的 5 次：从进 4.3 的那一行起，旧球消失、新球出现、按键打开隔的行数 | 1 次是 2、332、333；4 次是 3、333、334 |

- 所以时序准到 1 帧：检测在进 4.3 的那一帧或下一帧，之后的间隔和规则完全一样。求解器取多数的那一种：进 4.3 之后第 333 步新球出现，第 334 步起按键起作用（共 2.52 游戏秒）。
- “只算当前小节的变球器”和“所有小节的都算”在这些记录上结果一样：记录里球没有进过别的小节的变球器的范围，这一条没有被检验到。“同种的挡住更远的异种”也没有被检验到。

石球本身：物理核走石球用的是同一步，只是质量、推力、阻尼、摩擦、弹性换成石球的（都是读到的）。原版记录里石球在动、不接触的 3,978 步，竖直速度和“阻尼 0.3、重力”算出来的相差中位 3e-7（5 步例外）。
按键的推力也对过：石球不接触、按着键的 3,975 步里，水平速度每步的增量集中在 0.092 和 0.130（一个键和两个键，0.92 / 10 和它的 √2 倍）；木球 0.226、纸球 0.325 同样。
**石球贴着路面滚的那一步没有对照**：要按键方向（要视角），这次没做；记录里几乎没有不按键的步。石球落地的反弹，物理核是 0.173（两个弹性系数的几何平均），原版记录里量到的是 0.176 到 0.180。

### 在规划里

变球器在三层里都用得上：

- **粗层规划**不再绕开石变：落脚点照常铺进它的范围，只是“走进石变范围”的边多算 2.52 游戏秒的代价（按跟随器的步速折成 45 的路程）。所以规划线只在绕路更贵或没有别的路时才穿过石变。粗层不知道球种（开局是木球），木变不加代价。纸变仍然绕开。
- **跟随器**：通路本身穿过一个木变或石变的范围时，进去不算“球没了”；进去以后变球：等 332 步，新球静止出现在悬停点，再走一步（只受重力），然后带着新球种接着沿通路走。球歪进一个不在通路上的变球器，和以前一样算走不下去，不会悄悄变球。
- **细搜**：搜索的每个状态带着球种。一个状态进了木变或石变（异种）的范围就变球，搜索从新球接着搜，球种不同的状态分开记。搜出来的走法可以是“木球一段、变球、石球一段”，路线里照这样分段；它的容错率也按这几段重跑（扰动后的重跑必须穿过同一个变球器）。进纸变仍然算走不下去。

别的：

- 物理核按上面的规则结束一次推演，并说出是哪个变球器。同种的变球器不结束推演。
- 变球在路线里是单独的一段，时间照算。一个小节的结果带着进来和离开时的球种，下一小节用离开时的球种接着解。
- 细搜的起点只取最后一次变球之后的状态。路线变过球的小节不搜备选路线，搜孤岛的那一种细搜也不穿变球器。
- 路线清单里每一段带球种，变球单独成一项（见 [files.md](files.md)）。

实际跑过的：

- 一条和变球器范围一样窄的假想走廊，中间放石变：不开变球时细搜 2 万次过不去，开了就搜出“木球、变球、石球”三段（`tests/test_trafo.py`）。
- 一条假想的直路上先后放石变和木变：粗层规划线穿过去，木球变石球、石球变回木球，三段都走通，重放一致。
- 第 1 关第 1 小节的石变：木球从旁边按着键滚过去，球心离原点 4.271 时触发；新石球出现在原点上方 3.00，不按键落下停在原点上方 1.917（落差 1.08；目录按网格算的是 1.03 到 1.10）。
- 第 1 关重新解的结果见本页末尾“第 1 关重新解”。

### 没做的

- **粗层不带球种。** 它不知道一段路要哪种球才走得了，也不会为了某个机关特意去变球；“这里要石球”要等需要某种球的机关接进来才有。
- **别的小节的变球器。** 游戏只有几个变球器物体，在用到它们的各行之间搬来搬去，停在最后一次摆它的那一行，隐藏着也起作用；所以不是当前小节的变球器也可能在场。在不在场取决于各小节建立的次序，没有建模：现在只放当前小节的。
- **石球贴着路面滚的那一步没有对照**（见上）。
- 变球途中球没有刚体的那 2.5 秒里，按规则球被拉到悬停点；拉动的过程没有模拟（结果不依赖它）。变球途中能不能吃道具不知道，现在按“球在悬停点”算。
- 碎片（旧球炸开的碎片会撞醒冻结的机关、推动箱子）没有建模。
- 死亡之后球种不变、检测照常，这些等接死亡时再说。
- 开局的球种假定是木球（地图文件里没有）。

## Dome

代码：`coarse.in_sector`（把 Dome 变成它所在小节的固定几何）。Dome 是一个固定不动的刚体，物理核不需要新规则：它就是多出来的一块固定面，带自己的摩擦和弹性。

### 规则和依据

| 规则 | 数 | 依据 |
|---|---|---|
| Dome 是一个固定的凸包刚体，球碰它和碰路面是同一条接触规则 | | 读（脚本、模板）；导出网格里它的 480 个三角面就是那个凸包 |
| 摩擦 0.2、弹性 0.8（路面是 0.7、0.3）：和球的接触摩擦是两者相乘，反弹是两者的几何平均 | 木球 0.16、0.40；石球 0.10、0.283 | 读（数据表）；竖直落在顶上的反弹是测（重建引擎）：木 0.398–0.400，石 0.2823–0.2829 |
| 只在自己的小节是当前小节时在场；别的小节里它没有刚体，球碰不到 | | 读（脚本）；离开小节后消失是测 |
| 死亡不改变它 | | 推（按箱子、道具球的实测） |

### 对照

- 物理核里球竖直落在 Dome 上的反弹：木球 0.40、石球 0.283（`tests/test_dome.py`），和上表重建引擎量到的一样。这是同一条反弹规则换了弹性系数，不是另配的。
- **原版记录里没有干净的对照。** 24 条记录里球第一次碰上 Dome 只有两次（都在第 10 关、木球）。一次是落到路面和撞上 Dome 的斜面发生在同一个物理步：来速 11.85，记录里那一步之后是 8.75（水平 4.2、向上 7.66）；物理核按先碰路面、下一步再碰 Dome 算，出来是 5.8（水平 0.4、向上 5.77）。另一次那几步里按键在变，比不了。
- 所以“同一步里碰两个面”物理核算出来的速度偏小，这是物理核的接触求解本身的问题（一个点一个点地解），不是 Dome 特有的；贴地撞 Dome 当起跳台正好是这种情形，结果要打折扣。

### 在规划里

- **粗层规划**：Dome 是几何的一部分，粗层在它上面照常铺落脚点、连边，可以规划从 Dome 上面走；以前它是障碍，只能绕。粗层只有一张图，所以在它眼里每个小节的 Dome 都在场。
- **跟随器和细搜**用的物理核里，当前小节的 Dome 是固定面：碰它不再算“碰了摆放物”，可以滚上去、弹起来、拿它当起跳台；别的小节的 Dome 不在。
- 13 关里有 11 个 Dome（第 1、3、5、7、8、10、11 关）。

### 没做的

- 同一步里碰路面和 Dome 两个面时速度偏小（见上），没有修。
- 粗层在别的小节也把 Dome 当成在场。规划线要是在别的小节走到 Dome 上，跟随器会掉下去，变成一处断点；原版关卡里别的小节的路不经过那里。
- 没有单独验证 Dome 上的滚动（摩擦 0.16 下推不动、守不住的圈）：物理核用的是通用的接触规则加它的摩擦系数。

## 道具球

代码：`ballistics/props.py`（从目录读数、取当前小节的道具球、让它们落稳），物理核里多个球体的一步（`kernel._multi_tick`）。

道具球是没有脚本的自由刚体：半径 2 的球，各有自己的质量、摩擦、弹性和阻尼。这是第一种会动的刚体，物理核因此多了“几个球体一起走一步”，路线的状态也多了“道具球各在哪、动没动”。

### 规则和依据

| 规则 | 数 | 依据 |
|---|---|---|
| 道具木球、石球是半径 2 的球体；质量 2 / 10，摩擦 0.6 / 0.7，弹性 0.2 / 0.1，线性阻尼 0.6 / 0.2 | | 读（数据表、模板） |
| 道具纸球在游戏里是凸包，质量 0.2；这里当成同质量的球，惯量取凸包的 0.277·m·r² | | 读；当成球是**近似**：回答撞不撞得开、剩多少速度够用，滚动和摇晃的细节不对 |
| 只有当前小节的道具球在场；小节建立时在摆放位置新建，落一段后停稳、冻结 | | 读（脚本）；测（重建引擎）。这里让它们从摆放位置落到停稳，路线开始时已经冻结 |
| 冻结的道具球不是墙：被撞的那一步就按撞击得到速度并醒来 | | 测（原版记录：木球 4.835 正撞冻结的道具石球，当帧得 0.888；物理核 0.863） |
| 球撞球：沿两球心连线按质量分速度，恢复系数是两个弹性的几何平均，没有 0.2 的下限 | | 读；测（重建引擎：撞击那一步和这条规则相差 3% 以内） |
| 两球之间的摩擦在撞击里也起作用：滚动着撞上去的球被抬起，被撞的球被压向路面，之后路面拖住它 | 被撞球 10 到 20 步后剩规则的 0.45–0.56 | 测（重建引擎） |
| 停下来不动 0.3 物理秒后冻结 | 20 步 | 读（冻结规则的短期判据）；游戏还有“整组都静”等条件，这里只看它自己和贴着它的球 |
| 道具球不触发盘点、变球器、拾取和风扇 | | 读（脚本） |

物理核的做法：每一步所有球先各自移动、更新速度；然后“球对路面”和“球对球”的接触放在一起解。球撞球的那一下单独放在最后解一次（只在两个球之间），它对路面接触的影响从下一步才显出来。这样排是为了对上两条实测：撞击那一步被撞球得到的速度就是两体规则的值，路面的拖拽在之后几步。

没有道具球醒着、玩家球也没挨着哪个道具球时，走的还是原来那一步，逐位相同。

- **原版记录的直接对照做不干净。** 24 条记录里玩家球撞道具球有 39 次，但记录每帧一行，撞击前后隔着一到两个物理步，其间有按键、路面摩擦和别的接触，逐次比不出规则来；能确认的只有上面那一次冻结的道具石球。所以这里的依据主要是重建引擎上的实测。

### 在规划里

- **粗层规划**：道具球不再是障碍。粗层的图上没有它们的形状，只是“走进道具球所在位置”的边多算一点代价：纸球 2、木球 5、石球 30（按木球撞它们以后剩多少速度估的，只用来排序，是**假定**）。以前一排道具球挡住的路，粗层只能绕或者留作断点。
- **跟随器**：道具球的状态跟着球一起往前推演；它预看每种按键时各带一份道具球的副本，所以会“看到”撞开以后的结果。
- **细搜**：每个状态带着道具球的状态，道具球的位置不同算不同的状态；搜出来的走法连同它把道具球撞到哪都记在路线里，重放时一起重放，容错率的重跑也带着。
- 一个小节的路线每一段的起点和终点都带着道具球的状态；下一小节用自己小节的道具球，从它们停稳的位置开始。
- “不许碰摆放物”的规则不再包括道具球；箱子和机关仍然不许碰。

### 没做的

- 道具纸球当成了球（见上）。
- 撞击后第一步被撞球掉速偏快（见上）。
- 小节刚建立时道具球还在下落的那一小段时间没有算：路线开始时它们已经停稳。带着速度过盘点、马上撞上去的走法会有出入。
- 冻结的条件只看它自己和贴着它的球；游戏是“一个模拟单元里每个刚体都静才一起冻结”。
- 道具球掉到死亡区以下很深才被游戏移走；这里掉出关卡就算没了。
- 道具球能撞动机关、被机关撞动，这要等机关接进来。
- 死亡以后道具球复原（只有死亡能让被推进死局的道具球回来），等接死亡时再说。

## 落石

代码：和箱子在一起，`ballistics/props.py`（`PARTS`、`part_boxes`）和物理核的 `kernel._multi_tick`。

落石是两块：下层地面上一只自由的箱子（4.1 × 4.1 × 5，质量 1.4），托着一块 5 × 5 × 5 的路块（质量 1.6）。路块挂在竖直滑轨上，只能上下滑。把箱子从路块底下顶出去，路块落下来，补上上层的路。

物理核里它们是两个“只滑不翻的方块”，路块多一条约束：只能沿自己的竖直轴动。没有另写“落石”的规则：箱子顶不顶得出去、路块落不落，都是接触和摩擦算出来的。两块的位置和大小从导出网格里它们的形状读出来（那就是模板的形状放到地图摆放的位置）。

- **粗层规划**：两块都不再是障碍。走进箱子所在位置的边多算 40，走进路块（没落时它挡着上层的路）的多算 80（**假定**，只用来排序）。

- 13 关全部小节里的道具球、箱子、落石一共 216 个，都让它们落稳试了一遍：第 1、2 关全部能停稳；别的关里有一些 10 游戏秒后还在动（斜坡上的道具石球本来就会一直滚；另有几只箱子没停稳，原因没有逐个查）。

## 活式木栅栏

代码：`ballistics/props.py`（`PARTS`、`part_boxes`）、物理核的 `kernel._multi_tick`，粗层是 `solve.gate_edges`，“先推开再通过”在 `staged.solve_sector`。导出：`export.placed_hulls`。

栅栏立在上层路口上。靶子板、横杆和栅栏是一个刚体（质量 3），横杆卡在凹槽里。球在下层路上从靶子外侧沿机关自己的 +x 顶靶子，栅栏顺着凹槽滑出路口，球再回到上层路口，从让出的缝里过。

物理核里它就是这几个刚体：
- **滑块**：三块碰撞形状合成一个不转的刚体。靶子板和横杆是长方体，栅栏是梯形棱柱，球碰栅栏按它真实的十二个三角面算。它不碰路面和钢轨（游戏里的 Floor 组）。
- **凹槽**：一块底板加两面侧壁，固定不动，只碰滑块，球从它里面穿过去。
- **填充块**：路口处的一块薄板，固定，是球滚的路面。

滑块靠压在凹槽底板上的摩擦（0.6 × 0.7）停住，靠侧壁导向，靠靶子板顶到侧壁的端头停在满程。没有另写“栅栏”的规则：推多远、推不推得动，都是接触和摩擦算出来的。

碰撞形状不是显示网格，模板里有、导出的网格里没有。现在导出把它们写进地图文件（`hulls`：每个凸包的顶点和三角面，放在地图摆放的位置）。13 关的地图文件都重新导出了，除了多出这一项，其余一字不差。

### 规则和依据

| 规则 | 数 | 依据 |
|---|---|---|
| 滑块：一个刚体，三个凸包，质量 3，摩擦 0.6，弹性 0.4，阻尼 0.1 / 1；不碰路面和钢轨 | | 读（数据表、模板、碰撞组） |
| 凹槽：底板和两面侧壁，固定，摩擦 0.7，弹性 0.4；只碰滑块，球穿过它 | | 读 |
| 填充块：固定的路面，摩擦 0.7，弹性 0.4 | | 读 |
| 凸包都在各自物体的坐标系里 | | 推（几何：凹槽底板就是凹槽物体的显示网格；横杆底面和滑块显示网格的底面重合；靶子板的面在 −5.0、侧壁端头在 0，满程正好 5.0） |
| 只在自己的小节是当前小节时在场 | | 读 |

- **粗层规划**：关着的栅栏挡路。球心离栅栏不到球半径的边从图上拿掉；只有靶子板例外：从被推的那一面顶它就是推它，球越过那个面才算挡路。其中推开（滑 4.95）以后就让开的那些，按栅栏记下来（第 1 关两处各约 300 条）；另外记下推它的位置，就是下层路上靶子板正前方的那个点。

- **跟随器和细搜**：滑块是场景状态的一部分，跟着路线走。
- 推开后的缝（球心约 0.57 宽）粗层上能不能落下点，要看格点。

### 没做的

- **粗层上没有栅栏的顶面**：横杆、靶子板、栅栏顶都是会动的刚体，不在粗层的网格里，上面没有落脚点。第 10 关第 1 小节两条原版记录（SR10、HS10）都是木球骑着横杆、从靶子板和栅栏中间“超”过去的（球心在机关的 x −3 到 −1、高 1.4–2.2），粗层规划不出这条路。和“踩着箱子走”是同一个缺口。
- 第 10 关第 1 小节现在整节解不通：中段要变纸球、借风扇上去，后段有箱式浮板，都还没接。
- 滑块往 −x 被推离凹槽、掉下去：物理核里会发生（它不碰路面），没有对照。
- 滑块不转：实测横着顶时它斜 2.9°。
- 球骑上横杆横向带动栅栏（目录里的“超”）没有对照。

## 推板

代码：`ballistics/props.py`（`PARTS`、`_hinge`、`stoppers`）、物理核的 `kernel._multi_tick`（铰链体），粗层是 `solve.board_edges`。导出：`export.placed_hulls`（带上物体的坐标矩阵）、`export.stoppers`。

推板立在路面尽头，后面是约 9 到 10 宽的空隙。球到它附近时它醒来，朝来球一侧后仰，靠板根的楔块压在路面上。球从路面一侧把它推过顶点，它就向前倒下，远端搭在空隙另一边的托座上，成了一座桥；推它的球紧跟着从板上过去。推的地方就是过的地方。

### 铰链体

这是物理核里第一个会转的刚体，后面的跷跷板、T 型板、浮板、双向挡板都能用它：
- 状态是绕固定轴的角度和角速度。木板的两块碰撞形状跟着转。
- 重力作用在脚本给定的质心上；惯量用实测的。
- 碰撞形状取模板网格顶点围成的凸壳。推板的板身网格只有 10 个三角面，不是封闭的，不能直接用。
- 接触按接触点算力臂。碰路面和托座用凸壳自己的角点，角点不带半径：楔块离铰链只有 0.7，角点带 0.05 的半径就会让后仰角少 3°。
- 板倒下时末端每物理步走 0.7 左右，比托座还厚，所以角点会提前算接触：这一步按速度会走到的面先算作接触，只许它正好走到面上。
- 不转的刚体（道具球、箱子、落石、栅栏）走原来的算法。改之前和改之后，三份对照脚本的输出逐字相同。

**托座**（Phys_FloorStopper）以前导出时整个丢掉，现在写进地图文件，每个连通块是一个凸包：
- 挡机关和道具，不挡玩家球（托座是 Ball 组，和玩家球同组）；
- 也挡 Floor 组的机关（跷跷板、栅栏滑块；这一条做跷跷板时改正，原来写成了不碰栅栏滑块）；
- 摩擦 0.7，弹性 0.3。

### 在规划里

- **粗层规划**：推没推倒是粗层状态的一位（见“粗层的状态”）。推板前方路面上的落脚点（离铰链 1.5 到 4、离板中线 2 以内）各有一条边，穿过板连到对岸（离铰链 10 到 14），边的类型是“滚过去”，代价是路程再加 5（**假定**，只用来排序）：
  - 立着时，木球、石球走这条边就是推倒它，状态变成“倒下”；纸球推不倒（读），没有这条边。从背后推不倒，所以立着时只有这一个方向。
  - 倒下以后，任何球两个方向都能走。
  - 立着时，粗层的链接要是直线穿过板，也不通。
- **跟随器和细搜**：板是场景状态的一部分；推不推得倒、球能不能过，由物理核算。
- 球压在刚体顶上时，现在算作“被托着”，跟着路走、算到达，和压在路面上一样。以前只有路面算；这一条对箱子、落石的顶面也起作用。

- 板醒前竖直冻结着被撞没有建模（游戏里没找到这种情况）。
- 醒来时那一下回弹没有：物理核里直接停在后仰角。
- 别处的后仰角：物理核里大多是 −15.40°，也有 −12.29°（第 9 关第 4 小节）、−20.29°（第 11 关第 4 小节）、−16.2° 和 −16.3°。原版记录里有几处是 −13.9°、−14.4°、−14.7°，没有逐处核对。
- 第 13 关有 6 块托座超过 16 个角，没有放进物理核（那里的推板由路面接住，照样停在约 90°）。
- 石球、纸球推板没有原版记录对照。

## 纸球

代码：`ballistics/coarse.py`（`StateGraph`）、`ballistics/solve.py`（`fan_lifts`、`state_graph_for`）、`ballistics/staged.py`（`_fan_bounds`）、`ballistics/fine.py`（按状态评分）。

纸球现在是求解器会算的球种：路线可以在纸变变成纸球，一路以纸球走，再在别的变球器变回来。

### 物理核里的纸球

还是半径 2 的球，用表里的数（目录里的“选项一”）。不接触的飞行和风扇推力以前已经和原版记录对过（见“风扇”一节）。贴地就不准了：

| | 物理核 | 目录 |
|---|---|---|
| 平地单键稳定速度 | 13.9 | 12.19–12.36（推） |
| 平地斜按两键 | 19.7 | 中位 13.28、p90 15.63（原版记录） |
| 贴地走时不接触的物理步 | 0 | 八到九成（游戏里纸球是跳着走的） |

- 纸球贴地的时间偏短 13% 到三成以上，按偏乐观看待。
- 单轨上游戏里的纸球容错极低，物理核里的球却稳稳地滚，纸球走钢轨的路线要当作没核实。
- 判死：物理核是球心进了死亡区才判死；游戏里拿球的网格盒和死亡区做盒测试，木球实测是顶面上方 2 以内，纸球按网格盒推是 2.03 到 3.53。这一条对三种球都一样，以前就有，这次没改。
- 目录里的“选项三”是 157 点的凸多面体刚体，跳动、漂移、停住都对得上，但对初始朝向极敏感、计算量大，这次没做。

### 在规划里

- **变球**：纸变不再是终点，粗层也不再躲开它。路线经过纸变就变成纸球，花 2.52 游戏秒，和石变一样。
- **球种是粗层状态的一部分**（见“粗层的状态”）：进哪种变球器的范围，往后就是哪种球；风扇的上升边只有纸球有；纸球推不倒推板，也推不开栅栏。
- **跟随器**照计划走，计划里球种变的地方就是它在物理核里变球的地方。**细搜**里每个状态按自己的球种和机关状态取剩余距离来评分，所以变成纸球以后的状态看得到风扇的上升边。
- **风扇的上升边**（`solve.fan_lifts`）：只给纸球，用物理核推演出来。每个风扇：
  - 入口取轴附近的落脚点，最多 3 个；出口取离轴水平 4 到 32、从原点高度到原点上方 25 的落脚点，按位置散开取最多 40 个。
  - 出口范围参照了第 2 关原版记录里纸球乘风扇的 31 次：落点离轴 7 到 29（p10 到 p90，最远 61），比原点高 −1 到 20。那些是 TAS 记录，走法可能偏向 TAS 的捷径，所以范围放得比量到的宽。
  - 推演：纸球从入口静止起，先按键滚到轴附近，在风扇柱里升一会儿（0、40、80、130 步各试一次），再按键朝出口去，到了就松键。最后落在出口上、被托着，才收这条边；进了变球器的范围（在空中也算），离出口 5 以内，也算到了。
  - **两个风扇连乘**：在一个风扇柱里升起来，推向 25 以内的另一个风扇柱，到了（离轴 6 以内）往回按一下刹住（0、16、32 步），在那根柱里再升一会儿（0、60、120 步），再推向出口。第 2 关第 3 小节上石变就是这样：先在底座的风扇里升，再进高一层的风扇。
  - 出口除了散开取的，总加上离本小节变球器 6 以内的落脚点（上升边常常是去变球器的路）。
  - 按键取方向最接近的那个。以前按点积取，斜键长 √2 倍，朝正东的出口也会选到东北、东南的斜键，球被吹偏；第 2 关第 3 小节因此一条上到石变的边都没有。
  - 每条边再用两档判定（下档：只有一定会推的才推；上档：可能推的都推）各重放一次。两档都到的算稳；只有一档到的标“看朝向”，代价乘 1.5。
  - 第 2 关推演出 527 条（以前 119 条），273 条是连乘的。按两档分：96 条两档都到，65 条只有下档到，166 条只有上档到，200 条两档都不到（只有最合的那档到）；两档都不到的也留着，和只有一档到的一样代价乘 1.5。
  - 第 3 小节 137 条。落到石变旁边的 78 条都是连乘的：33 条只有下档到，45 条两档都不到。所以上到石变这一步全看球的朝向。
- **两档都查**（`staged._fan_bounds`）：一个小节解完以后，纸球经过风扇附近的每一段，都在两档判定下各重放一次，记下能不能到同一个终点。只查选定的走法，不放进搜索。

## 跷跷板

代码：`ballistics/props.py`（`PARTS`）、物理核的铰链体（见“推板”），粗层是 `solve.seesaw_edges`。

一块长 14.8、宽 5 的板挂在铰链上，质心在轴上方。倒向哪头就停在哪头，压在那头的托座上，离水平 19.5°：低端和路面齐平，高端比路面高约 4.9。
- 木球、纸球从低端按着键冲上去，从高端飞出，落到对面，板不翻；
- 石球够快就能过轴，把板翻到另一头，随板过去；
- 从高端来的球掉进缺口。

物理核里它是推板那种铰链体，碰撞组是 Floor：穿过路面和钢轨，只靠铰链和两头的托座托着。

### 规则和依据

| 规则 | 数 | 依据 |
|---|---|---|

### 物理核这次改的两处（推板也受益）

- **一个两边都让不开的接触不再解。** 板端的一个角点碰到托座的侧面，法向正好沿铰链轴：铰链不让它沿轴动，托座又固定，算出的法向冲量到了三万多，摩擦上限跟着变大，把板锁死，球再怎么压都不转。现在一个接触两边能让开的量小于 1e-6 时就不解它。
- **铰链体的每个角点旁边多一个往里收 3% 的接触点。** 板宽 5、托座长也是 5，板端的角点正好落在托座两端的侧面上，被判成碰侧面，板端就没有东西托着，会陷下去 1.5°。多了往里收的点，板端总有点落在托座顶面上。
- 不转的刚体走的还是原来的算法，三份旧对照脚本的输出仍然逐字相同。推板的对照重跑了：13 关 35 块全被托座接住（89.03–89.90°），原版记录 26 次里推倒 15 次，12 次过 85° 的时间差在 −0.2 到 +0.13 秒，和改之前一样。
- 代价：铰链体的接触点从 8 个变成 16 个。第 2 关第 3 小节纸球在推板前的那一次 10 万次搜索从 44 秒变成 67 秒；别的 10 万次搜索仍是 13 到 14 秒。

### 在规划里

- **粗层规划**：哪头低是粗层状态的一位（见“粗层的状态”）。低端外的路面上（离轴 7.5 到 12、离板中线 2 以内）各有一条边，穿过板连到高端外的对岸（离轴 8.5 到 16），两头各一组。边的类型是“滚过去”，代价是路程再加 5（**假定**）。
  - 只有从低的那头上板的边在；放好时哪头低，按质心偏向哪头定。
  - 石球过板就把它翻过来，之后另一头低（测：入板 4.95 起都翻）；木球、纸球过去，板不动（测）。
- **跟随器和细搜**：板是场景状态的一部分；翻不翻、过不过得去，由物理核算。粗层的状态从场景读：相对放好时转过 −10° 以下算翻过去了（倒向第一头约 +9.6°，翻过去约 −29.6°）。

### 没做的

- 石球在坡上滚动偏弱（见上）：翻不翻的门槛比实测高一点，粗层按“石球过板就翻”算。

## 软木桥

**规则**（目录 `P_Modul_29`，【读】和【测·重建引擎】）：九块木板串成的吊桥。木球、纸球走上去不断，实测木球 15 次、纸球 18 次全部过桥。玩家石球的球心到第 6 块木板原点三维 4 以内，第 6、7 块之间的铰链就断开，石球随那一段掉下去，测到每物理秒 10.04 都越不过缺口。断了的桥只有在本小节丢一次球才复原。

**在粗层里**（`solve.cork_edges`）：桥的两头取它木板凸包沿它自己的 x 轴（放好时的方向）的两端，不看它在地图上朝哪个方向。两头之外 0.5 到 4、离中线 2 以内、和桥头高度相近的路面位置，各连一条边到另一头之外横向最近的位置，两个方向都有；代价是这段路的长度（【假】：按跟随器的步速过桥；实测过桥 0.62 到 1.02 游戏秒）。只有木球、纸球能走这些边（`coarse.CORK`）。

它没有状态位：石球一上去就压断、随桥掉下去，断了的桥要丢一次球才复原，所以活着往下走的球不会遇到断桥。区域分析的第三步照样列出它的两个状态。

物理核里没有软木桥（木板是摆放物，碰到就停），所以按物理核推演的 `solve --roll` 不用这些边，只有不推演的默认三步用。

**第 2 关第 3 小节**：接上以后，区域图上断点最少的走法就是标准走法，只在最后跳下长条末端时留 1 个断点（见 [solver.md](solver.md) 的“区域”）。

## 落石：粗层区域分析

目录 `P_Modul_34`【读】【测】：路块和箱子分开取摆放的凸包。落石**未落**时上层缺口不补，和落下位置相交的下层边保留；**已落**时，落程 4.78，以新顶面沿本地 X 接上层两岸，并封住穿过落下路块的下层边。粗层按原图看未落时的下层连通；不模拟箱子在下层的占位和移出后的去向。会撞到未落路块的已有通行边不能在未落时用；未知的上层断点不当作已证实的通路。检查起飞边只读取缓存里已有的几何，不另算起飞。

石球可以在下层从箱子本地 Z 的两侧顶，实际需要助跑并持续顶住；木球单次最多只挪 1.73，纸球推不动（目录【测】）。操作处是箱子这一面外面、球心在箱子侧面的底和顶之间的路面位置：这样的球撞得到它，下面是平地、钢轨还是槽都一样（钢轨上球心比平地低 1 左右）。落下的路块只封住球心比它顶面低的边：球心在顶面以上的是从它上面过（那时它的顶面就是上层的路）。粗层只在找到操作处时给石球一条原地切换边，不检查助跑和推箱距离；推完还得用原来的路绕回上层。只有死亡复位，状态图不加复位边。`--without` 移除路块和箱子的规则，下层不封，上层也没有补缺口的路块。

## T 型板：粗层区域分析

目录 `P_Modul_37`【读】【测】：立姿仍用原粗层网格当障碍。从板脚 +X 一侧、沿中线朝 −X 推，石球能推倒，木球要助跑约 12（【假】粗层一律认为有足够助跑，目录实测在撞前速度 9.75–11.5 的区间有倒有不倒）；纸球不能推。切换只在操作处原地发生，不连到板面。

**倒**状态将凸包以铰链为轴转到实测约 94.9° 的静态姿态（凸包的刚体框架原点就是铰链【读】），沿本地 Z 接通横头两端的另一条路。板脚立姿让出的路只在两端有粗层位置、沿线有固定路面支撑且不碰倒姿包围盒时恢复【假】；没有支撑依据就不补。`--without` 只恢复符合地面支撑条件的板脚旧路，不搭横头。只有死亡复位，状态图不加复位边。

**第 5 关第 4 小节**：三块落石一层叠一层，一块的上层路是下一块的下层路。开局状态下按次序推下三块，0 个断点到目标（31 次连接）；开局就让任何一块已经落下，都要 1 个断点，因为先落下的会封住后面还要走的下层。

两种机关用自身摆放轴和世界坐标凸包计算位置。【假】常用容差：路面球心高差 0.8（T 型板的操作处和两岸的落脚处），岸边距凸包 2.5，横向错位最多 1.25；封路和倒姿净空用按球半径扩张、留 0.2 容差的包围盒，短路支撑每隔最多 0.5 取样并允许 0.35 的贴地误差。它们和软木桥一样，边在 `solve.state_graph_for` 现算，只供默认区域分析使用。

## 箱式浮板：粗层区域分析

目录 `P_Modul_41`【读】【测·重建引擎】：相邻中心间距读 `pitch`。从任一入口沿列中线走，到第 n 个箱子要过 n 个。纸球直冲实测可靠地过完 8 个，粗层放行任意列长；木球上限 `wood_max` 取 `wood_boxes_by_entry` 里多箱结果的最低下界（当前是 3 个），长列也只可到前 3 个。目录正文说石球最多过 1 个，但数值表没有给石球的上限，粗层仍按 0。慢速试次只过了 1 个，所以即使短列也要【假】有够用的助跑；区域分析不验速度。

同小节按中心间距连列【假：距 `pitch` 最多差 0.25，整列中心离直线最多 0.25、高差最多 0.25，相邻方向和各自摆放 X 轴的夹角余弦绝对值至少 0.98】；不把孤立的箱子当作一列。朝向取首尾摆放中心，两头取首末箱的世界坐标凸包外端。匹配两岸【假】：岸点距端 0.5–4、离中线最多 2，球心相对端箱顶加球半径的高度差最多 2.5；两端有同高岸点时仍按横向最近配对，双向连，代价取两点之间的距离。缺凸包不补路；只有一端有岸点时仍可从那里上列，再去较低的路。

箱顶旧位置不是静止路面。在区域分析现算的图里，把整列凸包覆盖的水平带（含箱缝）上、距箱顶加球半径的球心高度 0.8 以内【假】的采样点去掉。穿过这条带的旧边也筛掉（包括直线估计的断点；起飞和风扇只读已有轨迹）。明确从下面或上面绕开的边仍可保留。粗层缓存、物理核、跟随器和细搜都不改。

从能到的第 n 个箱子可往两侧离开；到最后一个还可沿列从末端离开。只连筛完顶面带后、整列水平凸包外的粗层路面点（`kind == 0`），不限落点区域。落点不得高过箱顶球心高度（沿用岸点高度容差【假】，容差内的负落差按零算）。落差为 h 时，到整列凸包边及可离开箱子所对应的侧边或端边的水平距离都须不超过 `reach(h) = v√(2h/g) + 余量`【假】；侧边沿列方向允许箱子的轴向半宽。h 接近零时也能接旁边的同高路。速度 v 取 `pitch / seconds_per_box` 的速度上界（区间用最短时间）；目录 `paper_seconds_per_box`、`wood_seconds_per_box` 用游戏秒，先乘 `units.time_factor` 换物理秒，再与物理核已有的 `GRAVITY`（每物理秒平方）同用。余量取一球半径【假】。这只估离开时的水平射程上界，不验遮挡、着陆或实际速度，偏乐观。

这类边由入口岸点直接指向落点，不添回边；两端同高原有的过列边照旧。代价为沿列到离开处的长度加水平落距【假】。同一入口岸点、离开方向与落点滚行区域按进来的球种各留一个代表，优先能兼顾更多球种、再取代价较小的边；代表点相同则合并球种掩码。第三步的箭头和明细标出是从离入口第几个箱子（侧面−/侧面+ 是列坐标的两个横向，或末端）去哪个区域、哪些球能用。

不模拟箱子转动：压转后约 22–35 游戏秒才摆回【推】，只有死亡能立刻复原。和软木桥一样，粗层假定活着往下走的球不回头重走同一列，所以不分配状态位；双向边只表示可以从任一端首次过列，不保证立即折返也能过。第三步逐列报告哪些球能过、走法是否使用、拿掉整列后的最少断点数。`--without` 指定一列中任一个摆放名，即拿掉整列连接，不恢复已筛掉的箱顶位置和边。

## 双向挡板：粗层区域分析

`P_Modul_19` 每个摆放物有一位：开局 A 姿态。A 姿态只填 A 路，三种球两向都能过【测】；B 姿态改填 B 路，三种球能过（两向通【假】）。在 A 姿态，石球从 B 路本地 +X 一侧往 −X 推立片，翻的同时过 B 路，A 路断开【测】。B → A 从 A 路本地 −X 一侧往 +X 推，翻的同时过 A 路，B 路断开；这条是按对称性推出的【推：未实测】。两向均让木球推（要助跑【假：粗层不验速度】），纸球不能推。死亡回 A，图不加复位边，也不另加翻转中的状态。

两段缺口的本地 X 范围、两路的本地 Z 范围、立片顶高从目录 `gap_x`、`lane_z`、`standing_flap_height` 读；用摆放的三根轴把世界坐标凸包和粗层球心转回本地。A 的平片和 B 的立片按所在车道从凸包找；反姿态的 A 立片用 A 平片的 −X 端和 B 立片的厚度近似【假】。球心在立片底和顶之间即可接触，不要求球在平地球心高度，钢轨和槽里的球也算。岸点用已有路面点匹配【假：距缺口端不超过球半径加 2.5、横向错位不超过 1.25、同名义路面球心高差不超过 0.8；操作点距立片的轴向距离减球半径在 −0.2 到 2.5 内】。

旧图仍按摆放姿态缓存。现算状态图只限制依赖板面的旧边和穿过立片的边；板面用凸包高度加球半径的球心带【假：上下各放宽 0.8】，立片只查凸包近似盒所占的 X 带，下方和横侧留球半径减 0.2 的余量，不向顶面上方扩张【假】。钢轨有自己的支撑，不因与板面同高就当作板面；只在碰到立片或落脚点依赖板面时限制。起飞、风扇只查已有轨迹和落脚点；独立的低层、从立片上方越过的边不因挡板而屏蔽。没有板顶采样时，A 路按目录和已有两岸点补边；B 路按两岸点补 B 姿态通行边；找不齐岸点就留断点。旧 `gap` / `bridge` 不是通行证明，不升级为真的滚行。

第三步列出两态的实际连边、拨动地点和球种、固定开局姿态后的断点数，以及走法里先开哪条路、同时失去哪条路。`--state 名字=A/B` 改开局姿态；`--lock` 固定该姿态（默认 A）；`--without` 拿掉挡板，两段缺口都敞着，没有依赖板面的通行边。只在 `solve.state_graph_for` 的默认区域分析现算，不改缓存或 `--roll`，不推演刚体、助跑或翻转时间。

## 粗层的状态

代码：`ballistics/coarse.py`（`StateGraph`）、`ballistics/solve.py`（`state_graph_for`、`_link_rules`）、`ballistics/staged.py`（按状态规划和“操作”）、`ballistics/fine.py`（按状态评分）。

粗层规划不只是“在哪个落脚点”，还带着简单的状态：球是哪种球，每个机关处在哪种状态。角度、姿态、滑了多少这些细的数只在物理核和细搜里。

| 状态 | 取值 | 从物理核的场景怎么读 |
|---|---|---|
| 球种 | 木、石、纸 | 当时的球 |
| 活式木栅栏 | 关、开 | 滑块沿机关 +x 滑了 4.5 以上算开（推到底是 4.95 到 4.98，测） |
| 推板 | 立着、倒下 | 转过 60° 以上算倒下（倒下停在约 90°） |
| 跷跷板 | 哪头低 | 相对放好时转过 −10° 以下算翻过去了 |
| 落石 | 未落、已落 | 只在默认区域分析；开局未落，不从物理核读 |
| T 型板 | 立、倒 | 只在默认区域分析；开局立，不从物理核读 |
| 双向挡板（P_Modul_19） | A 姿态、B 姿态 | 只在默认区域分析；开局 A，拨动并过另一条路是同一条边，不从物理核读 |

一个小节的状态有 3 × 2^机关数 种（第 2 关第 3 小节：一个栅栏、一块推板、一个跷跷板，24 种）。默认区域分析再计入落石、T 型板和双向挡板，每个摆放物各占一位。只取这个小节的区域：重生点、终点和小节里摆放的东西围成的盒子，四周各放宽 60。

**边按状态有无：**
- 路面上的边和链接：通常不分状态；被机关挡住的边例外。进变球器的范围就变成那种球，花 2.52 游戏秒；已经是那种球就不花。
- 风扇的上升边：只有纸球有。落在变球器的范围里，就落成那种球。
- 栅栏：推开后才通的边只在“开”时有；石球在推它的位置有一步“操作”，从“关”到“开”。
- 推板：立着时，木球、石球从前方路面推倒它到对岸，状态变成“倒下”；倒下以后两个方向都能走。
- 跷跷板：从低的那头上板到对岸；石球过板就把它翻过来。
- 链接（缝、桥，都是断点）按两点之间的直线看（**假定**：链接本来不说怎么过）：
  - 直线穿过变球器的范围，过去就是那种球；
  - 直线撞上关着的栅栏或立着的推板（按摆放时的形状），那时不通。

  以前链接不管这些：第 2 关第 3 小节的规划用一处链接从纸变上方跨过去（球还是木球），又在纸球推不倒推板时用一处链接穿过立着的板。

**怎么规划。** 到终点还有多远，对每个状态各算一遍（从终点倒着做 Dijkstra，状态跟着边变）。规划从当时的状态往前走，每一步取“边的代价 + 落点在新状态下还有多远”最小的那条。测试守着：往前走出来的代价等于倒着算的。

**解小节时：**
- 规划从物理核场景读出的状态出发；每走完一段，从场景重新读状态，再规划。
- 规划里的“操作”（推栅栏）不交给跟随器去滚：路线走到那个位置（2.5 以内）就停，在物理核里按住键推 1.5 游戏秒，再从新状态规划。推完状态没变，这一步就从粗层拿掉。
- 规划里的上升边也不交给跟随器：跟随器只走到那个风扇（离轴 5 以内，和上升边的入口一样），然后按这条边自己的走法推演（`solve.ride`）：先滚到轴上，再照造这条边时的各段按键，每段按到它的点为止。到了才算这一段；没到，这条上升边就照以前那样交给跟随器和细搜（它们常常自己找得到上去的路，第 2 关第 5 小节就是这样），不再按它的走法推演。跟随器在那之前就走不下去的，从它这一段里最后一个在风扇边上的状态起推演。
- 过不去的断点留成断点以后，球放在断点那边静止，从那里按当时的状态重新规划（机关的状态照断点之前的）。
- 细搜给每个状态打分时，按这个状态自己的球种和机关状态取还有多远，所以搜到“推倒了推板”的状态，看到的是推倒以后的路。

**这次顺带修的：**
- 起飞边的助跑起点在变球器范围里的，按那种球推演（见 [solver.md](solver.md)）。以前一律按木球推，木球在范围里第一步就停在范围上，所以起点在范围里的一条都没有：第 2 关第 3 小节石变所在的平台没有路下来。第 2 关因此多了 116 条起飞边（纸球 72、石球 44）。
- 风扇的上升边落在变球器范围里，落成那种球（以前还算纸球，那 78 条上到石变的边因此接不上后面的路）。
- 风扇上升边和推栅栏的按键按方向选（见“纸球”“活式木栅栏”两节）。
- 下面几处是请 4 个代理各看一块改动、独立复查出来的，都对过代码，能写成小例子的加了测试：
  - 以前上升边是把它的轨迹当路点交给跟随器追。纸球在风扇柱里追不上：第一次从软木桥东头解第 3 小节时，球在风扇底座边上停了 80 轮（这一条是实际跑出来的，不是复查）。
  - 推栅栏要规划正好从推它的那个落脚点出发才会推；跟随器停在离落脚点 2 以内，重新规划多半从旁边的落脚点出发，于是一直不推、空转到轮数用完。现在 2.5 以内就推。
  - 一个别种的球已经在变球器范围里（机关的边能把球放到那里）：倒着算说走不下去，往前走又不花变球的时间。现在两边都花。
  - 从粗层拿掉一条走不通的边，以前会把同一对落脚点之间别种的边一起拿掉，而机关的边又拿不掉；现在只拿那一种，机关的也拿。
  - 上升边在半路进了变球器的范围（落点本身在范围外），以前粗层还当它是纸球；现在造边时记下它变成了哪种球。
  - 助跑起点在别的小节的变球器范围里的起飞边，在这个小节不算：这个小节里球到那里不变球。
  - 过不去的断点之后，以前接着走被“操作”或上升边截断的那半截计划，会把推它的位置或风扇当成终点停下；现在重新规划。
  - 截掉一段失败的推演以后，细搜不再从截掉的那部分起步。

### 第 2 关第 3 小节的规划

项目主人给的标准走法：变纸球，过软木桥，借两个风扇上到石变，变成石球；过跷跷板推开栅栏，绕回来推倒推板；再变纸球，走过推板之后那段斜着的木板路面，跳下去。

粗层现在的规划（只看地图，不推演）：

| 从哪里起 | 规划 | 代价 | 链接 |
|---|---|---|---|
| 软木桥东头，纸球 | 连乘两个风扇上到石变，变石球 → 从平台起飞，下到风扇底座那层 → 过跷跷板，把它翻过来 → 推开栅栏 → 回头过跷跷板，又翻回去 → 推倒推板过去 → 一处链接下到低处 → 起飞到终点 | 1779 | 1 处，最后那一跳 |
| 小节起点，木球 | 在纸变前面用一处桥链接（18 长，直线擦着纸变的范围外边）直接到推板前方，推倒推板过去，结尾同上 | 2435 | 2 处 |

- 从软木桥东头起的那条，到推倒推板为止和标准走法一样。
- 从起点没选它，是因为软木桥还没接：粗层上它是一处约 1000 的链接，从起点经软木桥走标准走法约 3000，比用那处桥链接（2435）贵。软木桥接进来以后，这一段不再要链接，标准走法约 1950，应当会被选中（估算：软木桥东头的 1779 加上从起点过去的路程和变球）。
- 推板前方那块路面和起点那边没有路相连（标准走法是绕过栅栏回来的），起点那条规划的桥链接跨的是一段空。
- 从第一个纸变起、以纸球走的规划，也有一处桥链接：[919, 48.7, −344] 到 [929, 48.7, −324]，从立着的推板旁边跨过去（直线不碰板），同样跨的是一段空，然后接最后那一跳。纸球推不倒推板，它只能这样绕。
- **最后那一跳**：每种球的规划都在那里用同一处链接（[933, 48.7, −203] 到 [930, 35.9, −188]），粗层没有起飞边。在物理核里从那个台沿滚下去：木球、石球掉出关卡；纸球静止起步、一直按着前进键，飘了约 50 远，落在 [933, 2.7, −152]，接着滚进小节尽头的石变。这就是标准走法里的“跳下去”。粗层的起飞边是木球推演的，所以没有它；要有它，起飞边得按球种分开推演。
- **实际解了一遍**（物理核，跟随器和细搜，细搜每处 10 万次），从软木桥东头、纸球静止起：
  - 跟随器走到风扇 18_01 边上，然后按上升边自己的走法推演。去石变的上升边，从球实际到风扇时的状态起没有到的。
  - 先试过“没到就从粗层拿掉”：78 条一条条拿掉以后规划退回西边，最后留下 B3（起点那处跳到推板前方的桥链接）和 F1 两个断点，不通。
  - 现在没到就交给跟随器和细搜：细搜在风扇那里 10 万次没找到上去的路（F1），规划改走跷跷板东头，跟随器在 [980, 48.7, −367] 一次次走不下去、细搜一次次只跨过几格，到轮数用完。跟随器的断点每次都算新的一处，“同一处跨过 3 次就留成断点”管不到它；这是以前就有的缺口，这次没修。
  - 这些上升边是从入口静止、正在轴上起步造出来的，从那里重放都到；球实际到风扇时偏离轴 4 左右、已经在往上升，就不到了。把“升一会儿”改成“升到造边时的高度”再试，也一条都不到。它们本来就脆：两档判定都不到的 45 条，只有下档到的 33 条。
  - 所以上到石变之后的几步（翻跷跷板、推开栅栏、推倒推板）在求解里还没跑到过，只在粗层规划里有。
  - 在“拿掉”的那一遍里，最后那一跳纸球由细搜跨过去了（B1，扰动 20 次都到），再到终点。
- 标准走法里推板之后“再变纸球”，规划没有：规划一直是石球，走到那处链接。纸球的起飞边有了以后，经过第二个纸变（[927, 42.7, −261.5]）那条路才会比链接便宜。
