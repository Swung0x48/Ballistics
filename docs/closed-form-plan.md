# 计划：全部换成闭式判定，删掉按时间步的推演

下文记录改造的顺序和验收办法。第 1、2 步已落地；第 3 步已换成闭式，已加入绕棱与分段反弹，按四关验收后才决定是否重建全关。后续步骤还未改。

## 决定

项目主人决定：

- 所有推算都用闭式直接得出能或不能，**不按时间步一步一步往前推**；
- 原来每一处按时间步的实现，都换成闭式判定的**等价实现**；
- **不许按步采样**：不能沿时间、弧长、轨迹或钢轨位置等距试点来判定接触、支撑或可达。直接解方程／不等式，或用有界区间和求根隔离边界。粗层约 1 单位的落脚点网格、纯画图或路线显示不在此限；显示折线一旦拿去判遮挡，就不再是例外。
- **检验的金标准是 SimTool 和游戏自己的模拟**，不和旧的按时间步的版本比。旧版本只在换下来以后、删掉以前，用来列出区域分析的结果变了哪些（作为报告，不作为验收）。

## 闭式的基础：引擎自己的离散递推，按等比数列直接求和

引擎每个物理步（1/66 秒）做这几件事：
- 速度乘一个阻尼系数 d；
- 加上按键的冲量（力 ÷ 质量，每个键一份）；
- 竖直方向再减去 g/66。

这是常系数线性递推。第 n 步的速度和位置有精确的闭式解（等比数列求和），不用一步步推。它和逐步递推在数学上相同，浮点上不会逐位相同。对不对以 SimTool 和游戏的模拟为准（见下面“怎么检验”）。所有闭式判定都用它：

- **飞行**：
  - 竖直位置 y(n) 是 n 的闭式函数。先用连续形式的 Lambert W 解出落到某个高度的步数近似值，再检查相邻的整数步，得到确切的落地步。
  - 水平方向：不按键时，落点就是一个点。按键时，每个键给一份冲量，方向沿视角的前、右（视角是 90° 的整数倍，`physics.key_push`）；两个键是两份相加，所以斜向是 √2 倍。随时换键能到的位移，是这 9 种推法的凸包：一个沿视角轴摆放的正方形，圆心和半边长都是 n 的闭式函数，对角能到 √2 倍。“一个键还是两个键”由这条引擎规则直接得出，不用另定。
  - 落点区域和这个正方形相交就能到。
- **滚动**：
  - 沿坡的有效加速度 = 推力 ÷ 1.4，再减去 5/7 倍的重力沿坡分量（目录、[game/physics.md](game/physics.md)）。
  - 速度和距离、用时之间都有闭式（一样是等比数列，或者它的连续形式加 Lambert W）。
  - 用来算“助跑 s 长以后的速度”、“过这段要多久”、“爬不爬得上这个坡”。
- **反弹**：法向速度乘以目录里的弹性（木球撞地 0.245【测】），切向不变，再接飞行的闭式。
- **风扇**：
  - 风扇在它的作用盒里给的是恒定冲量（目录、`fans.rules`）。
  - 盒内竖直方向一样是线性递推。能不能升到出口高度、升到那里要几步，都有闭式。
  - 出盒以后接飞行的闭式。

**墙挡不挡**：每个候选落点用恒定的世界轴推力代表一条可达轨迹；第 3 步优先试可行区间两端的速度，受阻时补查中间值和两段输入。第一块能托住球的接触面是实际落点。代表轨迹被挡不等于先松键、再按键等其它轨迹也被挡。查法：
- 球心到三角面所在平面的距离等于球半径的时刻，是“位置在某个方向上的分量 = 常数”的方程，同样能用 Lambert W 直接解，再看交点在不在三角面里，这是精确的；
- 碰棱和角时，用解析坐标界排除整段，再在根所在的步内弦上解到棱、顶点的二次距离式。不得用沿曲线取点替代。

## 边的时间成本，可以用实测值替换

项目主人要求：图上从一个节点到下一个节点的每条边，都带一个时间成本作为权重；这个值是用闭式推算出来的估计值；它要写进输出的路线文件，并且容易配置，训练时可以用实测值替换估计值。

- **每条边的时间**（游戏秒）：起飞边 = 助跑段的滚动用时 + 飞行段的落地步数；风扇抬升 = 风柱里升到出口的步数 + 出风柱后的飞行；机关边 = 目录里量过的秒数（推栅栏、翻跷跷板、过软木桥、乘升降机，秋千、沙袋另加等窗口）；变球 2.52 游戏秒。区域里的滚动也有时间：沿粗层图的路面路径（不是直线），按滚动闭式算，进下一段时带着速度。每个时间标依据（`[MEASURED]`、`[DERIVED]`、`[ASSUMED]`、`[READ]`）。
- **走法按时间选**：先看断点最少，再看时间最少（取代现在的“连接数最少”）。每条走法输出总时间和分段时间。
- **和标准走法比**：标准走法（项目主人给的几段、[game/levels.md](game/levels.md)）写成同一张图上的一串边，用同一套权重算时间，和找到的走法并排列出：总时间差多少、差在哪几段。第四步的捷径路线也一样比。
- **成本表**：求解时写出 `<名字>-costs.json`，每条边一行：稳定的键、估计值、依据、怎么算的。键不用图里的内部编号（重建以后会变），用关、小节、边的种类、球种、起点和终点的世界坐标（取整），以及机关的摆放名和状态，例如 `L01/S1/launch/W/(-152,31,-353)->(-152,18,-370)`。
- **覆盖文件**：`--costs <文件>` 按同样的键给实测值（加来源、样本数），求解时覆盖估计值，没覆盖的用估计值；也能按种类整体覆盖（所有变球、某种机关）。走法按覆盖后的时间选。
- **路线文件升到版本 3**（项目主人定的）：每段写时间成本、来源（估计还是实测覆盖）和边的键，引擎那一侧拿键回填实测值。格式写进 [files.md](files.md)。

## 第 1 步之后定下的两处细节

- **按键可达范围**：用凸包（正方形）当“能到”的判定。离散按键能精确落到的点和凸包内任一点最多差一步按键冲量带来的位移（Δt²·F/m 量级，远小于粗层位置的间距），粗层判定不必再按离散按键复核。
- **接触距离**：碰面的判定用球半径加上量过的接触间隙 0.0099（`Params.floor`【测】：65 次落地都在这个间隙离开）。
