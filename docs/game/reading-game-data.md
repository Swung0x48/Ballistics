# 怎么读游戏数据

这一页说明游戏的数据放在哪、各自能读出什么、用什么读。读出来的内容在同目录的其他几页里：[scripts.md](scripts.md)（脚本和数据表）、[physics.md](physics.md)（引擎物理）、[rules.md](rules.md)（关卡规则）、[mechanisms.md](mechanisms.md)（机关）、[levels.md](levels.md)（关卡）。

Ballistics 自己只读地图文件和录下来的轨迹文件，不启动游戏。下面“读脚本”和“在引擎里做实验”两节用的是引擎一侧的工具，属于一次性的查证；查到的结果记在这些文档里，分析器不依赖它们。

## 依据的标注

这个目录里每条事实都标了来源：

| 标注 | 含义 |
|---|---|
| 【读】 | 从游戏自己的脚本、数据表或文件里读出来的 |
| 【测】 | 在引擎里跑出来、或在录下的引擎轨迹上量出来的，写明数据量 |
| 【推】 | 由读到的数值计算或推断的，没有实测 |
| 【wiki】 | 取自 Ballance 中文 wiki（ballance.jxpxxzj.cn，在线站打不开时用 Wayback Machine 的存档） |
| 【玩家经验】 | 熟悉游戏的玩家给出的说法，没有在数据上核对 |

只有【读】和【测】能当作物理规则的依据。【推】【wiki】【玩家经验】用来定方向、当答案对照，写进模拟之前要先核对。

## 游戏文件

| 位置 | 内容 |
|---|---|
| `<游戏>/3D Entities/Level/Level_NN.NMO` | 第 NN 关的地图 |
| `<游戏>/3D Entities/PH/<类型名>.nmo` | 摆放物的模板：部件的网格和它自己的脚本。共 26 个：`P_Modul_01/03/08/17/18/19/25/26/29/30/34/37/41`、`P_Box`、`P_Dome`、`P_Ball_Wood/Stone/Paper`、`P_Trafo_Wood/Stone/Paper`、`P_Extra_Point`、`P_Extra_Life`、`PS_FourFlames`、`PC_TwoFlames`、`PE_Balloon` |
| `<游戏>/3D Entities/` 下的 `Gameplay.nmo`、`Levelinit.nmo`、`Balls.nmo`、`AnimTrafo.nmo`、`Camera.nmo`、`Menu.nmo`、`MenuLevel.nmo`、`Sound.nmo`、`Musicfiles.nmo`、`Tutorial.nmo`、`Intro.nmo`、`Language.nmo` | 游戏逻辑、关卡构建、球、菜单、声音等的脚本和物体。哪个文件装哪些脚本是按名字对应的【推】，脚本清单见 [scripts.md](scripts.md) |
| `<游戏>/base.cmo` | 游戏的主合成文件 |
| `<游戏>/BuildingBlocks/physics_RT.dll` | 物理行为模块（2002 年的原版） |

## 地图文件里有什么

一张地图是一个 Virtools 合成文件，里面只有**几何**和**组**【读】。一个物体对游戏意味着什么，全看它在哪些组里：

| 组 | 含义 |
|---|---|
| `Phys_Floors` | 路面，固定的碰撞体 |
| `Phys_FloorRails` | 钢轨，固定的碰撞体 |
| `Phys_FloorStopper` | Stopper：只挡机关和道具球，玩家球穿过 |
| `DepthTestCubes` | 死亡区 |
| `PS_Levelstart` | 起始盘点（四团火，装饰） |
| `PR_Resetpoints` | 重生点，按顺序；第一个就是出生点 |
| `PC_Checkpoints` | 盘点，按顺序 |
| `PE_Levelende` | 飞船 |
| `Sector_01`、`Sector_02`… | 这个小节里摆放的东西 |
| `P_Modul_01`、`P_Box`、`P_Ball_Wood`、`P_Trafo_Stone`、`P_Extra_Point`… | 某一类摆放物的占位物体 |

地图里**没有**的东西：

- 行为脚本。全部来自游戏自带的文件。
- 机关的部件。地图里每个摆放物只有一个占位物体（给出位置和朝向），部件来自 `3D Entities/PH/<类型名>.nmo`，加载关卡时由脚本读入【读】。
- 路面和钢轨的摩擦、弹性。它们来自游戏构建关卡的脚本用的表（见 [scripts.md](scripts.md)）。
- 出生时的球种。由关卡槽位决定：第 1 到 12 关木球，第 13 关石球【wiki】。

自制图和原版关卡是同一种文件，约定相同【读】。

## 读地图文件，不启动游戏

`.nmo` 的格式由 libcmo21 项目的 BMap 库解析。两种用法：

- **Python 绑定 `pybmap`**。Ballistics 用的就是它，见 `ballistics/nmo.py` 和 [../files.md](../files.md)。读出每个物体的名字、世界矩阵、网格（顶点和面）和所在的组。
- **Blender 加 Ballance Blender Plugin（bbp_ng）**。插件自带 BMap，可以把地图导入 Blender 再用脚本导出。

要注意的：

- 物体名可能是西文或中文编码，`nmo.py` 依次试 cp1252 和 gbk。
- 矩阵是行向量的写法，平移在最后一行。
- 读 PH 模板时，组里有些成员不是三维物体，读名字会失败，跳过即可。
- 这条路读不到行为脚本。数据表读不读得到没有核实。

核对过的【测】：第 1 关用这条路读出的 21,763 个地图三角面，和运行中的游戏为固定物体持有的三角面逐个相同，坐标差为 0；出生点和三个盘点的位置也相同。

## 读脚本（要启动无头引擎）

脚本在内存里是一张行为图：根脚本下面是一层层子图，最底下是行为模块（BB），BB 之间有连线，每个 BB 有输入参数、输出参数和本地参数。

读它用 BallanceMMO 的无头工具 `BallanceMMOSimTool`：它在无头引擎里加载真实的游戏目录，通过菜单进入关卡，然后把内存里的行为图打印成文本。

```
<SimTool> --root <游戏> --level 2 --ticks 700 --dump-at 690 <选项>
```

工具在第 200 tick 左右通过菜单请求关卡；`--dump-at` 要小于 `--ticks`。游戏目录只读使用。

| 选项 | 输出 |
|---|---|
| `--list-scripts '*'` | 所有根脚本和它们的所有者 |
| `--dump-script "根脚本名"` | 缩进的树：每个 BB 一行，带本地参数、输入参数（标明来源）、输出参数，以及 BB 之间的连线和延迟 |
| `--describe-script 名字` | 更结构化：带 BB 的 id，逐项列出输入、输出、本地参数和带 id 的连线 |
| `--dump-array 名字` | 一张数据表，例如 `PH`、`Checkpoints`、`ResetPoints`、`Physicalize_Floors` |
| `--list-entities 前缀`、`--list-bodies-at T` | 实体的位置；某个 tick 上存在的刚体 |
| `--list-placement --list-group 组名` | 组成员的世界包围盒和世界矩阵 |

能读到的：Physicalize 的固定、摩擦、弹性、质量、碰撞组、阻尼，以及 Set Physics Force / Hinge / Slider / Spring 等 BB 的参数，都是当前值。

陷阱和限制：

- **`--dump-script` 打印向量时把 y 和 z 互换了。** 打印的 "a,b,c" 实际是 (a, c, b)。例如重力打印成 0,0,-20，实际是 (0, -20, 0)。地图文件里的字节是没有互换的顺序，可以用来核对【读】。
- `--describe-script` 只描述同名根脚本里的第一个。关卡构建时复制出来的机关脚本都保留原名，要看全部副本得用 `--dump-script`。
- BB 的 id 是那一次运行里的编号，换一关、换一个版本就变，只能用来对照同一次的输出。
- 打印的是那一刻的值。运行中被改过的参数在不同 tick 上不一样；来自其他 BB 输出的参数，在没执行过的分支里是 0 或空。
- 没有打印网格顶点和面的选项。
- 只有当前小节的机关有刚体（见 [rules.md](rules.md)）。要看某个机关的参数，直接读它脚本里 Physicalize 的参数。
- 第 1 关有新手教程，会把世界暂停：不加别的选项时球到第 2204 tick 才出现【测】。
- 工具的“自由运行”是原版逻辑，只把随机数模块换成确定的；它的联机会话模式会改掉死亡复位、小节停用等逻辑，读原版行为时不要用会话模式的结果【读】。

**BB 的含义不在脚本里。** 脚本只给参数；每个 BB 做什么，编译在 `physics_RT.dll` 等模块里。查含义看 Ballanced 项目（这些模块的重写版）的源码。原版用的是 2002 年的模块，和重写版有少数差异。物理引擎内部的量（步长、时间因子、速度上限）脚本里也看不到。

## 在引擎里做实验（引擎一侧）

同一个工具有一个投放场景：把指定球种的球放到指定位置，从某个 tick 起按住方向键，记录球和机关每个 tick 的位姿。[mechanisms.md](mechanisms.md) 里“推不推得动”和爬坡的数字就是这样测的。

```
<SimTool> --root <游戏> --level N --drop 名字 球种 --drop-at X Y Z --drop-second-ball 球种 X Y Z --drop-sector S --hold 玩家 方向 TICK --placement-trace 文件 --ticks N
```

要注意的：

- **球种编号在这个工具里是 0 纸球、1 石球、2 木球。** Ballistics 的轨迹文件用的是 0 木球、1 纸球、2 石球。两套不要混。
- `--hold` 的方向是朝另一颗球定的，所以要再放一颗球当目标；一次运行里换不了方向。
- 在原版关卡的真实位置上测，不要在平铺所有机关的试验图上测：同一个推板在试验图上的表现和在原版位置上不一样【测】。
- 起点要选在有路面的地方。盲选的起点很多直接掉下去。
- 第 1 关要加 `--world-options SESSION_CLOCK`，否则教程暂停世界，球不动。
- 逐 tick 的轨迹文件一次几十 MB，解析完就删。
- 这个场景跑的是联机会话世界，不是纯原版逻辑；已知结果能对上两条，不等于处处一致。

引擎的存档回滚（引擎一侧的说明，没有在这里重测）：只能在进程内做，一份快照是物理引擎的状态块加脚本记录，回滚后重放逐 tick 相同；历史只保留 96 tick；抓取约 2.2 毫秒，恢复约 3.1 毫秒；没有给外部程序用的接口。

自制图进引擎：只能放进 1 到 13 号关卡槽，槽号决定出生球种、天空和音乐【读】。

## 录下来的引擎轨迹

标定物理核用的是别处录好的引擎轨迹（文件），两种形式，读法见 `ballistics/trace.py`：

- **逐帧文本**：每帧一行，帧号、球的实体名、3×3 朝向矩阵、位置。
- **运行文件（.npz）**：每次观测的球位置、速度、球种、视角的四分之一圈数、引擎自己的最近接触间隙和法线、摩擦接触数；每个执行帧的帧时间和按键。

要注意的：

- 录制是 264 帧每秒，两帧对应一个物理步；两帧之间引擎报的是同一个状态。`Run.ticks()` 取出状态变化的那些观测。
- 速度的单位是每物理秒（见 [physics.md](physics.md) 的“时间和单位”）。
- 轨迹里没有自转。可以从逐帧朝向反推（相隔两帧的朝向相除）：大小和纯滚动只差 4%，方向和纯滚动的中位偏差约 17°，原因没查清，**不可靠**【测】。
- 目前只用过一条：第 1 关的一条 TAS 竞速轨迹（SR 1:14.457，20,483 帧，木球）。
