# 目录：球、机关和关卡规则

`ballistics/things/` 是一份数据：关卡里除了普通路面以外的每样东西各一条——三种球、箱子和道具球、十四种机关、变球器、分数球和生命球，外加管一关怎样运行的规则。
每条写的是给路线规划和物理核用的结论：它有哪些刚体和数值，状态机怎样（什么让它变、变了以后怎样、要多久、死亡和换小节以后怎样），三种球各能拿它怎样，它怎样改变路线，还有什么不知道。

它只是数据，什么都不模拟。物理核和求解器现在还不读它（见 [design.md](design.md)）；它先把“要模拟什么”定下来。

## 怎么看

```bash
python -m ballistics things                  # 一览：每条的类别、摆放类型、三种球的结论、依据的分布
python -m ballistics things P_Modul_37       # 一条（条目的 id）
python -m ballistics things P_Trafo_Stone    # 也可以用地图上的摆放类型名
python -m ballistics things death_timing     # 一条共用规则
python -m ballistics things --check          # 检查全部文件的格式
```

代码里：

```python
from ballistics import things
cat = things.load()
cat["P_Modul_25"].machine["transitions"]     # 推板的转移
cat.of_type("P_Extra_Point").numbers         # 按摆放类型找条目
cat.rules["death_timing"]["numbers"]["control"]
```

## 一条里有什么

| 字段 | 内容 |
|---|---|
| `types` | 这一条管的摆放类型名（球和规则没有） |
| `uses` | 用到的共用规则（`data/rules.json` 里的 id，同一条规律只写一次） |
| `bodies` | 每个刚体：形状（凸包的网格名和尺寸，不含顶点）、质量、摩擦、弹性、阻尼、碰撞组、初始是否冻结、怎样运动（自由、铰链、滑动……） |
| `forces` | 它施加的力和规律 |
| `numbers` | 给规划和物理核用的关键数：阈值、时长、区间 |
| `machine` | 状态机：状态、标志、转移、死亡和换小节以后怎样 |
| `by_ball` | 木、石、纸三种球各自的结论和一句说明 |
| `route_effects` | 它怎样改变路线：挡路、开路、载球、限定球种、时机、单向、危险…… |
| `model` | 要模拟它，物理核最少需要什么 |
| `unknowns` | 还不知道的，和怎样查清 |

**状态和标志。** 状态是对路线有区别的离散形态（挡着、推开了、倒下了、不存在）。和形态无关的布尔量（冻结着、邻近检测开着、推力开着）写成标志，不乘进状态里。

**三种球的结论**只是粗分：`passes` 直接通过；`pushes` 能推动、推开或推倒；`breaks` 把它弄坏；`rides` 骑着或被托着走；`blocked` 过不去或推不动；`no_effect` 无关；`depends` 看情况。
具体条件在说明和数值里。“能推倒”不等于“推倒以后能从它身上过”：T 型板、活式木栅栏、落石的**操作处**（球去操作机关的地方）和**通过处**（路线经过机关的地方）是分开的。

## 每个事实的依据

每个数、每条转移、每条结论都带依据：

| 依据 | 意思 |
|---|---|
| READ（读） | 从游戏本身读到的：脚本、数据表、模板，或重建引擎的源码 |
| MEASURED（测） | 在引擎里量到的 |
| WIKI | 只有社区 wiki 这样说 |
| DERIVED（推） | 由读到和测到的事实推出，`how_zh` 说怎样推的 |
| ASSUMED（假定） | 没有核对 |
| UNKNOWN（未知） | 不知道 |

读到和测到的事实另有 `src`，说依据是哪一类材料（数据表、脚本转储、模板、引擎源码、逐帧记录、专门的测量、别的工具那边的回答……）。这些材料是本机的游戏数据和笔记，不在仓库里，所以目录只写类别，不写路径。

测到的事实还有 `engine`，说是在哪里量的：

| engine | 意思 |
|---|---|
| `original` | 2002 年原版物理库回放录像的逐帧记录 |
| `retail` | 零售版游戏 |
| `x87_soft` | 重建引擎按 x87 精度编的构建，回放模式。它的物理代码和原版逐位对照过，但回放模式的帧方案没有对照 |
| `rebuilt` | 重建引擎的可移植构建，66 Hz 工具帧。和原版是同一套规则、不同的舍入 |

`rebuilt` 上量的区间、静止角、时长可以用；逐帧的数和混沌的单次结局不能当原版的值。

## 约定

- 时长是游戏秒（1 游戏秒 = 132 个物理步），速度是每物理秒，长度是游戏里的单位。
- 帧数都标帧率：评估按 132 fps（每帧 1 个物理步）；“66 Hz 工具帧”是测量工具的一帧（2 个物理步）；“行为帧”是脚本的一帧。
- 门槛如果是“同一速度有倒有不倒”的过渡区，照实写区间和次数，不写成一个数。例如木球按着键撞 T 型板：撞前 9.75 以下推不倒，11.5 以上都推倒，中间有倒有不倒。
- 名词照 [game/terminology.md](game/terminology.md)。

## 来历和限制

- 目录由本机的规格（每样东西一份长文，带引文和出处）生成：刚体表和每一项的依据从规格里取，文字是对规格的摘要。生成时机械地检查过三件事：文字里的数字在规格里出现过（只是字面上找得到，不保证用对了地方；写明是换算或合计出来的数不查）；规格的每条转移、路线影响、未知都被带进来或说明了为什么不带；文字里没有路径、文件名和内部编号。
- **摘要的句子没有逐句人工核对。** 结论和合并转移的取舍是写摘要时判断的，可能有读错的地方；用到某一条时，以它标的依据为准，拿不准就回到引擎里量。
- 这几条所依据的规格没有做过“对路线的影响”那一轮审查：石球、关卡流程、秋千（08）、单摆（17）、沙袋（26）、跷跷板（30）、箱式浮板（41）。
- 大多数实测是在重建引擎上、一两处摆放上量的，套用到同类型的其他摆放；条目里注明了只量过哪一处的地方。
- 自制地图里才会出现的情形（例如倒置悬空的 T 型板）这一阶段不建模。
- 已知的捷径在相关条目里各有一句（第 5 关第 2 小节的道具石球加 T 型板在 T 型板一条；不推靶子、越过栅栏的走法在活式木栅栏一条；第 9 关第 3 小节的秋千到风扇在秋千一条），都没有在引擎里验证过，留作以后检验规划器的对照。
