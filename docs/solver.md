# 求解器怎么工作

`solve` 默认只用粗层，分三步（`ballistics/regions.py`，下面“区域”一节）：

```bash
python -m ballistics solve --mesh data/Level_02-mesh.npz --map data/Level_02-map.json --out data --png out
```

1. **区域**：把每个小节分成只靠滚动就互相到得了的区域。写出 `<名字>-regions.json`，加 `--png` 时每个小节一张 `<名字>-regions-s<N>.png`。
2. **连接**：列出区域之间靠什么相连，找跨断点最少的走法。写出 `<名字>-links.json`，加 `--png` 时每个小节一张 `<名字>-links-s<N>.png`。
3. **机关**：把每个机关当成简单的状态机，看它接通、断开了哪些区域，走到目标要不要它，走法按什么次序拨动它们、各为了什么。写出 `<名字>-mechanisms.json`，加 `--png` 时有机关的小节各一张 `<名字>-mechanisms-s<N>.png`。

`regions` 命令和不带 `--roll` 的 `solve` 一样。

加 `--roll` 是原来的求解器（`ballistics/staged.py`）：先粗后细，粗层规划通路，跟随器在物理核里沿通路推演，只在过不去的地方细搜。每个小节先得到一条标准路线，再从它出发找备选路线（`ballistics/shortcut.py`）。它慢得多：第 1、2 关各要半小时左右，大部分时间花在备选路线上（`--shortcuts 0` 只解标准路线，两关各约 5 和 11 分钟）。

```bash
python -m ballistics solve --roll --mesh data/Level_01-mesh.npz --map data/Level_01-map.json --sector all --png out
```

它写出每个小节的结果（`<名字>-staged-s<N>.pkl`）、所有路线的清单（`<名字>-routes.json`，格式见 [files.md](files.md)），加 `--png` 时还有每个小节、每条备选路线和整关的俯视图。

只看粗层的规划、不推演也不细搜：

```bash
python -m ballistics coarse --mesh data/Level_01-mesh.npz --map data/Level_01-map.json --png out
```

它对每个小节给出粗层的规划线（从盘点静止起步到下一个盘点）：多少个落脚点、多长、用了几条起飞边和几个台阶、有几处链接，以及每处链接附近 9 个单位内摆着什么；写成 `<名字>-coarse-plan.json`，加 `--png` 时画出整关和每个小节的俯视图。这条线只是位置，没有速度，也不表示球开得过去；它几秒到几分钟就能出来，适合先看一张新地图的全貌和粗层接不上的地方。

链接最远只连 25 个单位。盘点附近即使加上链接也到不了终点时，这条线从离盘点最近的、到得了终点的地方开始，前面那一段标成“没有规划”。原版 13 关的 68 个小节里有 7 个是这样（都在第 7 到 12 关），原因是现在只算木球、不算机关和风扇。求解器（`solve --roll`）遇到这种小节也是从那个地方开始规划的，但它没有把这一点说出来。

俯视图的高度用灰度表示（越高越深），钢轨和摆放物是蓝色；标题和线型的图例在图的上栏，刻度在下栏，都不压在地图上。

## 区域：粗层的连通关系

这是 `solve` 默认的三步（`ballistics/regions.py`）。它把粗层看成区域之间的连通关系，什么都不推演，第 2 关整关约一分钟（粗层的图要已经建好、缓存在 `--out` 下；没有时先建图，那要在物理核里把起飞边滚一遍）。

- **区域**：一个小节里，某一种球只靠滚动边（滚动、钢轨、钢轨尽头）就能互相到达的粗层位置，即这些边上的强连通分量，三种球各算一遍。状态有条件的边不并入区域：例如落石下层的边只在未落时放行，所以也要独立列为连接。别种球的变球器范围不算这种球的区域：球一进范围就被变了（游戏的规则，没有选择），所以横在路上的变球器把路面截成两段。例如第 2 关第 3 小节，开头那条直路上的纸变（`P_Trafo_Paper_01`）把木球的区域截断在它前面，木球不变成纸球就到不了十字路口和推板。一个位置因此最多在三个区域里，每种球一个；区域按球种编号（木 109、纸 3）。
- 走法从重生点下面的位置出发。重生点 3 个单位以内没有能到目标的位置时，也还从那里出发（结果就是到不了），不跳到远处能到的地方：那样得出的走法，重生点下面的球并没有。第 10 关第 1、3 小节就是这样：以前各报 0 个断点，是从离重生点 458 和 143 的地方算起的；现在是到不了，第 3 小节的升降机和秋千有区域规则，但这不保证能从重生点到达它们。
- **连接**：从一个区域到另一个的边，各带它要的条件和它改变的状态：
  - 起飞、下落、台阶、只能单向滚下的坡，任何球种；
  - 滚进或落进别种变球器的范围：从这种球的区域到那种球的区域，之后按那种球接着走；
  - 纸球乘风扇上升；风扇上的箱子还在时，相应上升边不放行；
  - 过开着的栅栏；石球在推的位置推开栅栏，木球也行（目录实测撞前 10.40 以上推得开，助跑【假】），推的位置可以在钢轨上；木球或石球推倒推板；从倒下的推板上过；从低端过跷跷板（石球会把它翻过来）。条件和 `coarse.StateGraph` 的一样。
  - 落石未落时保留下层的边，石球在下层原地操作；已落时下层封住，从上层路块顶面过。T 型板由木球或石球从板脚一侧原地推倒（【假】木球有约 12 的助跑），另一路从倒下的横头通过；有固定路面支撑时才补立姿让出的路。两者只用于区域分析，见 [机关说明](mechanisms.md)。
  - 过软木桥（`P_Modul_29`）：木球、纸球两个方向都能过；石球不能（`solve.cork_edges`，见 [mechanisms.md](mechanisms.md) 的“软木桥”）。
  - 双向挡板（`P_Modul_19`）：A / B 姿态各只放行同名路；木球（【假】有助跑）或石球从立片一侧推并过另一条路，同一步封掉原通路。B → A 按对称推出【推：未实测】。只用于区域分析。
  - 箱式浮板（`P_Modul_41`）：两端同高仍双向过列；从任一端进入，纸球可到整列，木球可到目录上限内的箱子（目前前 3 个，【假】有助跑），石球按 0。从可达箱子两侧或整列末端，按落差估计射程【假】，单向连到同高或更低的路面。没有状态位，只用于区域分析，见 [机关说明](mechanisms.md)。
  - 单摆（`P_Modul_17`）：固定面或钢轨有支撑的跨杆路，三种球可推过去；目录限位只挡让距不足的通过方向。杆无状态位，不模拟摆动；木球、石球从合适的推杆点原地操作，由另一端推倒推板或推开风扇上的箱子，只用于区域分析，见 [机关说明](mechanisms.md)。
  - 升降机（`P_Modul_03`）：三种球都从满载门洞进，推掉挡路墙门后乘到高度相合的路面、钢轨或下一台的满载门洞（纸球助跑足够【假】）；到出口同时置为用过。跨空档的出口也保留，但标未实测。不推演，只用于区域分析。
  - 秋千（`P_Modul_08`）：本地 X 方向的两岸双向乘过，三种球均可；木、纸须按键。沙袋（`P_Modul_26`）：固定路面或钢轨有连续支撑的横扫堵点，三种球均可等窗口双向通过。两者无状态位、只记时窗不计等待代价，不推演，只用于区域分析。
  - 粗层接不上的地方的“链接”（`gap`、`bridge`）算**断点**：没有任何东西表明那里过得去。
- **走法**：从这个小节的盘点，在（区域，各机关的状态）上找断点最少、其次连接最少的走法（区域带着球种）。前一个小节的走法以哪种球到达，下一个小节就从哪种球开始（第 1 小节假定是木球）。旁边另列粗层自己的最短计划（按点的那一条），压成区域的步骤，两者对照着看。

第一步写出 `<名字>-regions.json`，第二步写出 `<名字>-links.json`，区域名使用 `W68`、`S54`、`P4` 这样的写法（格式见 [files.md](files.md)）。加 `--png` 时每一步每个小节一张图。第一步的图：同色的点是一个区域（30 个点以上的，和盘点、目标所在的），300 个点以上的标了编号和区域里有的变球器。第二步的图：区域之外，细线是连接（颜色按种类）；断点最少的走法这样画：它经过的区域描黑框；它的每一次连接画成一支箭头，从离开上一个区域的地方指到落进下一个区域的地方，旁边的圆牌是第几步；在区域里变球的那一步，号码写在区域里。每一步是什么列在图下。区域内部不画线：在一个区域里滚动到得了任何地方，走法并不说球在里面怎么走。箭头只是这种连接的一个例子（代价最小的那一条），同样的连接可能还有很多条。

它说的是“粗层认为连得上”，偏乐观，读的时候要记着：

- 道具球不挡路（粗层把穿过它们算作加价，不算障碍）。
- 粗层的链接（`bridge` 最远 25）可以跨过变球器的范围或穿墙：没有软木桥时，第 2 关第 3 小节断点最少的走法是木球用一个断点斜跨过开头纸变所在的窄口，一共 2 个断点。接上软木桥以后，断点最少的走法就是项目主人给的标准走法（变纸球、过软木桥、乘风扇变石球、翻跷跷板、推开栅栏、翻回来、过栅栏、推倒推板），只在最后跳下长条末端时留 1 个断点：那里网格里没有路面，粗层也没有起飞边落到下面那块小平台上。它推倒推板以后不再变纸球，石球直接跳：两样都是 1 个断点，这样少一次连接。
- 台阶只是粗层的提议，没有在物理核里验证过。第 2 关第 4 小节的走法是木球滚进石变、石球连上 5 个台阶、再沿钢轨落进纸变，到达目标（`fewest_breaks: 0`）；实际求解（`--roll`）在台阶那一带留了两个断点。
- 起飞边是木球在物理核里滚出来的，石球和纸球也照样用。
- 连接还没有按游戏时间计代价，走法只比断点数和连接数。

第三步（`regions.mechanisms`）：

- **状态和放行**：栅栏（`closed`、`open`）、推板（`up`、`down`）、跷跷板（`low end at (x, z)`，用低端上板的位置命名；哪头是低端由它自己的铰链和质心定，不看它在地图上朝哪个方向）、软木桥（`whole`、`broken`）、落石（`standing`、`dropped`）、T 型板（`up`、`down`）、双向挡板（`pose A`、`pose B`）、风扇上的箱子（`present`、`cleared`，每摞一位）、升降机（`loaded`、`used`）。每个状态放行哪些区域之间的连接，哪种球能用；在哪里、由哪种球拨动它。双向挡板同时标出拨动时通过的路和随即断开的路。软木桥没有状态位：石球一上去就压断，随桥掉下去，断了的桥要在本小节丢一次球才复原，所以活着往下走的球不会遇到断桥。
- **要不要它**：把这个机关固定在开局的状态（拨动它的连接都拿掉；软木桥、箱式浮板则整座或整列拿掉），再找一遍到目标断点最少的走法。断点变多或到不了，就是**必需**（`needed`）；不变而走法用到了它，是**用到，可以绕开**（`used, can be bypassed`）；没用到，是**这条走法没用到**（`not used by this way`）。原走法就到不了时输出 `goal not reached`。
- **单摆**：逐杆列出三种球实际能推过去的区域与方向、限位挡掉的方向、走法是否用到及拿掉杆后的最少断点数。另列实际联动（目标、推杆点、球种、依据）；推板和箱子的 `switched` 也列出远程操作的来源。联动候选、是否靠近走法的断点以及空洞危险只提示，不作连接条件。
- **升降机**：逐台列门洞入口、各球种能到的出口及各自推几块、平衡顶面、出口面和挡墙；标需带速度和未实测的飞行空档。报告走法是否使用、拿掉平台后的最少断点数。纸球能助跑推下墙门【wiki】【项目主人确认】；标助跑足够【假】，不实际检验。
- **次序和为了什么**：沿第二步的走法，每次变球或拨动机关，找出后面第一处要用到这个新状态、而旧状态不行的连接。例如第 2 关第 3 小节：变纸球是为了乘风扇，变石球是为了推栅栏，第一次翻跷跷板是为了之后能从另一头翻回来，推开栅栏是为了之后过栅栏。
- **秋千和沙袋**：逐个列出有向连接、球种、周期和窗口参考、是否用到以及拿掉后的最少断点数；无状态位。不补边的摆放仍列原因。秋千的保护路面或失足危险、沙袋的撞击失败都只报告。

**假设（what-if）**：三步都可以在改过的关卡上再跑一遍，找“如果这样，会不会有别的走法”：

```bash
python -m ballistics solve --mesh data/Level_02-mesh.npz --map data/Level_02-map.json --out data --png out --without P_Trafo_Paper_01 --tag no-paper01
```

- `--without 名字`：这个摆放物不存在。变球器没有范围；风扇没有上升边（连乘两个风扇的上升边按它进的第一个风扇算）；软木桥、推板、跷跷板不能从上面过；栅栏不挡路（它放行的路一直都在）。落石没有上层补路，也不封下层；T 型板不搭横头，只恢复原板脚下有支撑的路。箱式浮板指定任一箱子即不再放行整列。双向挡板两段缺口都敞着，不补板面的连通。单摆的杆不存在，联动取消，两向恢复有固定支撑的过杆路，不移走轴下固定件。风扇上的箱子指定任一成员即移除整摞，上升边不再需要推开箱子。升降机没有平台，不能乘也不能从另一台落在其上。秋千没有斗，不能乘过；移除沙袋时，其挡住但有固定支撑的路两向通。只修改区域分析现用的边，不改粗层缓存。
- `--state 名字=状态`：这个机关开局就是这个状态（`0`、`1`，或上述英文状态名；跷跷板可用报告中的低端位置字符串，也可用 `tipped` 表示 `1`；升降机开局 `used` 即不能再进）。旧输入如 `关`、`已落`、`A姿态` 仍可用；带空格的值要加引号，如 `--state "名字=pose A"`。
- `--lock 名字`：这个机关的状态永远不变：栅栏推不开，推板推不倒（也就不能从推它的地方过去），石球过跷跷板不翻它，落石、T 型板和双向挡板保持设定的开局状态。锁推板也禁止单摆远程推倒；锁风扇上任一只箱子会锁住整摞的开局状态。升降机永远满载，不能乘，即使同时指定了 `used`。
- 都可以写多次。结果写成 `<名字>-<标签>-regions.json` 等（标签默认 `what-if`），文件头里记着用了哪些假设；不加这些参数时文件名不变。

例：第 2 关第 3 小节没有开头的纸变（`--without P_Trafo_Paper_01`）时，木球从盘点直接滚到十字路口、推倒推板过去，3 次连接、1 个断点（最后那一跳）就到了目标；软木桥、风扇、跷跷板、栅栏都用不上。所以标准走法绕那一大圈，是因为开头的纸变把木球挡在推板前面，纸球又推不倒推板。

第 2 关第 3 小节的结果：栅栏、推板、跷跷板、软木桥四个都是必需的，任何一个固定住（软木桥拿掉），到目标就要 2 个断点。第三步的图只框机关那一片：机关放行的连接画成粗线（实线：开局就放行；虚线：要先拨动它），原地拨动机关的地方画圈，图下列出每个机关和走法的次序。

## 四个部分

1. **粗层规划**（`coarse.py`）。在精确几何上每隔 1 个单位取一个“球能被托住的位置”，加上钢轨走线，连成图；摆放的东西（机关、箱子、道具球）都算障碍。从盘点到下一个盘点，沿粗层自己的边走；粗层接不上的地方用“链接”补上，链接很贵，只在真的不通时才用。规划里的每个链接，以及粗层只是“提议”的台阶，都是一个**断点**，带着只凭地图就知道的信息：间隙多宽、高差多少、中间摆着什么。
2. **跟随器推演**。在物理核里让球沿规划走，每 8 步决定一次按键：从球此刻的状态（位置、速度、自转）出发，把九种推力各按住推演一游戏秒，看哪一种沿通路走得最远、最早，而且不会让球掉出去或碰到摆放的东西；都不行时再试“先按一种 24 步、再换另一种”。球照最好的那种走 8 步，然后重新看。它不朝某个固定速度推，也不在哪里特意刹停：通路上的下落和腾空，球带着当时的速度就过去了。断点如果它自己就过去了，说明那只是粗层没连好；它走不下去的地方（不管是不是清单上的断点）才交给第 3 步。
3. **只在断点处细搜**（`fine.py`）。起点是球在刚滚过的这一段上有过的状态（所以远处的助跑也用得上）；目标是断点对面，或粗层自己的边能从那里滚到对面的任何位置。这一段的起点搜不到时，再把本小节更早的路段也加进起点。
   细搜找到第一个走法以后不马上停：再搜同样多的次数（至少 6000 次），最多留 10 个走法；然后挑一个——先看起点和按键时机扰动以后 20 次里还能到几次，再看多快；挑中的再试 160 次小改动（把某个键延长或缩短 8 步、换一个键、去掉一个键），更值就留下。一次按键的整段推演是物理核的一次调用（每秒约 8600 次试探，原来约 4400 次）。
4. **过不去的断点如实留着。** 不碰任何摆放的东西过了才算过。没过的断点就是断点：这时再把道具球去掉搜一次，只为了诊断挡路的是不是道具球，它的轨迹不采用；球被放到断点对面静止，只为了把后面的断点也列出来，这个小节算“不通”。

## 多条路线：孤岛和捷径

上面四步给出的是每个小节的一条路线，下面叫**标准路线**。粗层规划只走粗层自己的边，补缺口的链接只在别无他路时才用；所以一个托得住球、又通向盘点、但没有任何边通上去的地方（墙顶、护栏），永远不会出现在规划里，不管它能省多少时间。这样的地方叫**孤岛**。`ballistics/shortcut.py` 在标准路线解完之后做三件事：

1. **找孤岛。** 一片落脚点算孤岛，要同时满足：靠粗层自己的边（滚动、钢轨、从静止推出去的起飞）能走到标准路线经过的地方；从标准路线出发，靠粗层任何一种边都到不了它。对每个孤岛，估计“球从路线上落到它上面，最多能省多少时间”，按这个数从大到小排。
2. **从路线上搜过去。** 对排在前面的几个孤岛（`--shortcuts`，默认 4 个），让细搜从球在标准路线上有过的状态出发，在严格模式下（不碰任何摆放物）搜到孤岛上。细搜找到第一个走法就停，而最先找到的往往是最容易落上去的地方，不是最省时间的地方，所以每个孤岛最多搜三次：先只要“至少能省到最好情况一半”的落点；搜不到再放宽到任何落点；搜到之后再要一个更靠前的落点。
3. **从落点接着解。** 每个搜到的落点，都用同一个求解器从落地时的状态接着走到盘点（跟随器，走不下去的地方细搜，过不去的断点留着），拼成一条完整的备选路线。一个孤岛有几个落点时，取能走通里最快的那条。

每条路线（标准路线是 R1，备选是 R2、R3……）列出两个数：

- **预计时间**：这条轨迹本身的游戏秒，以及比标准路线多或少多少。另外给出它回到标准路线上的那一点领先或落后多少，因为之后的路段两条路线各自重新搜过，总时间里混着那一段的差别。现在的收益只有时间（SR）；HS 的分数没有算。
- **容错率**：路线上每一处细搜出来的走法，把起点扰动后重放 20 次，看还有几次能过；扰动有三档，1 倍是位置 0.03、速度 0.3、换键早晚 2 步，另两档是 3 倍和 10 倍。路线的容错率取它最弱的一处。跟随器走的路段是闭环的，不计入。

每个候选都列出来：没搜到的（写明试了多少次）、比标准路线慢的、留有断点的、排在 `--shortcuts` 之外没试的。

**这些路线是假说。** 它们是手写物理核里的轨迹，时间是物理核的时间，搜索只找到“一个”走法而不是最快的走法。它们准不准，由读这份清单的其他工具去评估。

还没做到的：

* 只找孤岛。标准路线自己晚些时候会到的地方，从高处直接飞过去也可能省时间，这一类还不提出；
* 备选路线都是从标准路线上分出去的，不会再从一条备选路线上找下一个孤岛；
* 下一个小节仍然从标准路线到达盘点时的状态出发，备选路线到达盘点时的状态只是记下来；
* 估计“最多能省多少”用的是粗层的长度和一个固定的步速，只用来排序，和最后算出来的时间可以差很多。

## 规则和界限

**次数上限**：细搜是随机试探，一次尝试 = 选一个到过的状态、按住九种推力之一 8 到 64 步。每个断点、每组起点最多试 30 万次（`--tries`），随机种子固定，结果可重复。到上限还没过，就留作断点，这只表示试了这么多次没试出来，不是证明过不去。

**规则只有一条**：推演中球不许碰还没有建模的摆放物（机关），因为它们会动。道具球、箱子、落石、活式木栅栏、推板和跷跷板已经是刚体，可以撞开、推走、推倒、压翻；纸球也是会算的球种；粗层规划带着球种和机关的简单状态（[mechanisms.md](mechanisms.md) 的“粗层的状态”）。球碰路面、钢轨、路沿、侧棱都是普通的接触，一视同仁。

**变球器**按游戏的规则触发（最近的一个、4.3 以内、和球不同种）。粗层规划可以穿过石变（多算 2.52 游戏秒的代价），跟随器沿通路穿过木变或石变时变球，细搜的状态带着球种、进了变球器就以新球接着搜；纸变仍然不进（[mechanisms.md](mechanisms.md)）。

**Dome** 是它所在小节的固定几何，带自己的摩擦和弹性，不算摆放的障碍；粗层也在它上面铺落脚点。

**风扇**也不算摆放的障碍：它没有刚体，只在物理核里给球一个向上的推力，而且只有正在解的这个小节的风扇在推（[mechanisms.md](mechanisms.md)）。

**分数球和生命球**不算摆放的障碍：它们没有刚体，球直接穿过。每条路线顺路吃到了哪些，按读到和测到的规则另外算出来写进结果（[mechanisms.md](mechanisms.md)）；搜索不以它们为目标。

**速度**：轨迹里球的速度从头到尾是连续的，每一段都从上一段结束时的状态接着算，段与段之间速度相差为 0。小节之间也一样：和正常游戏一样，下一小节从球到达盘点时的状态（带着速度）接着走；只有关卡开头，以及上一小节没通（要按球丢了、在盘点重生来算）时，才从静止起步。

下落和腾空的落点取决于球离开时的速度，所以粗层里它们不是“从这个位置到那个位置”的边，而是物理核推演出来的**起飞边**（`launch.py`）：球从台沿或钢轨尽头后方 0、8、16 或 32 个单位处静止起步，按住朝台沿的方向键，滚出去、飞、落地（空中继续按着或松开）；边带着助跑路线、起飞速度和落地速度。助跑都按木球推演，只有起点在变球器范围里的按那种球：在范围里的球就是那种球，木球在那里第一步就停在范围上。它们只用来告诉规划“这里能过去、大概这么走”。真正走的时候，跟随器是从球当时带着的速度出发往前推演的，不会先停下来。路面上只留不超过 1.5 的小台阶可以直接滚下去。

速度还没有做到的地方：规划的代价不是时间；跟随器只看一游戏秒远，看不到更远处该提前加速或减速；起飞边是从静止造的，带着速度才飞得过去的地方规划里没有对应的边，只能靠细搜（断点处的细搜，和上一节对孤岛的细搜）。

## 已知的不足

* 推箱子、推道具球、滑动的石块都没有建模。第 3 小节按正常玩法是把纸球推开，这个分析器现在算不了，所以那里是断点；
* 粗层规划链接时不看中间有没有墙，会把球带进走不出去的地方，要靠“退回更早的路段”补救；
* 轨迹没有优化，也没有分段做成证明；
* 飞船的形状不在网格里（路面在飞船前 21.9 处结束），第 4 小节的目标是飞船前最后一段路面；
* 只有木球；只做了第 1 关。

另有一种整小节一次搜到底的做法（`--whole strict`），只用来对照。
