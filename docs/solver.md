# 求解器怎么工作

求解器（`ballistics/staged.py`）先粗后细：粗层规划通路，跟随器在物理核里沿通路推演，只在过不去的地方细搜。

```bash
python -m ballistics solve --mesh data/Level_01-mesh.npz --map data/Level_01-map.json --sector all --png out
```

## 四个部分

1. **粗层规划**（`coarse.py`）。在精确几何上每隔 1 个单位取一个“球能被托住的位置”，加上钢轨走线，连成图；摆放的东西（机关、箱子、道具球）都算障碍。从盘点到下一个盘点，沿粗层自己的边走；粗层接不上的地方用“链接”补上，链接很贵，只在真的不通时才用。规划里的每个链接，以及粗层只是“提议”的台阶，都是一个**断点**，带着只凭地图就知道的信息：间隙多宽、高差多少、中间摆着什么。
2. **跟随器推演**。在物理核里让球沿规划走，每 8 步决定一次按键：从球此刻的状态（位置、速度、自转）出发，把九种推力各按住推演一游戏秒，看哪一种沿通路走得最远、最早，而且不会让球掉出去或碰到摆放的东西；都不行时再试“先按一种 24 步、再换另一种”。球照最好的那种走 8 步，然后重新看。它不朝某个固定速度推，也不在哪里特意刹停：通路上的下落和腾空，球带着当时的速度就过去了。断点如果它自己就过去了，说明那只是粗层没连好；它走不下去的地方（不管是不是清单上的断点）才交给第 3 步。
3. **只在断点处细搜**（`fine.py`）。起点是球在刚滚过的这一段上有过的状态（所以远处的助跑也用得上）；目标是断点对面，或粗层自己的边能从那里滚到对面的任何位置。这一段的起点搜不到时，再把本小节更早的路段也加进起点。
4. **过不去的断点如实留着。** 不碰任何摆放的东西过了才算过。没过的断点就是断点：这时再把道具球去掉搜一次，只为了诊断挡路的是不是道具球，它的轨迹不采用；球被放到断点对面静止，只为了把后面的断点也列出来，这个小节算“不通”。

## 规则和界限

**次数上限**：细搜是随机试探，一次尝试 = 选一个到过的状态、按住九种推力之一 8 到 64 步。每个断点、每组起点最多试 30 万次（`--tries`），随机种子固定，结果可重复。到上限还没过，就留作断点，这只表示试了这么多次没试出来，不是证明过不去。

**规则只有一条**：推演中球不许碰摆放的东西（机关、箱子、道具球），因为它们会动，而这里没有给它们建模。球碰路面、钢轨、路沿、侧棱都是普通的接触，一视同仁。

**速度**：轨迹里球的速度从头到尾是连续的，每一段都从上一段结束时的状态接着算，段与段之间速度相差为 0。小节之间也一样：和正常游戏一样，下一小节从球到达盘点时的状态（带着速度）接着走；只有关卡开头，以及上一小节没通（要按球丢了、在盘点重生来算）时，才从静止起步。

下落和腾空的落点取决于球离开时的速度，所以粗层里它们不是“从这个位置到那个位置”的边，而是物理核推演出来的**起飞边**（`launch.py`）：球从台沿或钢轨尽头后方 0、8、16 或 32 个单位处静止起步，按住朝台沿的方向键，滚出去、飞、落地（空中继续按着或松开）；边带着助跑路线、起飞速度和落地速度。它们只用来告诉规划“这里能过去、大概这么走”。真正走的时候，跟随器是从球当时带着的速度出发往前推演的，不会先停下来。路面上只留不超过 1.5 的小台阶可以直接滚下去。

速度还没有做到的地方：规划的代价不是时间；跟随器只看一游戏秒远，看不到更远处该提前加速或减速；起飞边是从静止造的，带着速度才飞得过去的地方规划里没有对应的边，只能靠细搜。

## 已知的不足

* 推箱子、推道具球、滑动的石块都没有建模。第 3 小节按正常玩法是把纸球推开，这个分析器现在算不了，所以那里是断点；
* 粗层规划链接时不看中间有没有墙，会把球带进走不出去的地方，要靠“退回更早的路段”补救；
* 轨迹没有优化，也没有分段做成证明；
* 飞船的形状不在网格里（路面在飞船前 21.9 处结束），第 4 小节的目标是飞船前最后一段路面；
* 只有木球；只做了第 1 关。

另有一种整小节一次搜到底的做法（`--whole strict`），只用来对照。
